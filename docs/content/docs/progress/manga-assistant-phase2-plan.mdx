# 漫剧助手第二阶段实施计划

## 目标

在现有画布中新增一个名为“漫剧助手”的 Script 节点形态，复用现有 Script 生成链路，升级为可审核、可锁定、可追溯的漫剧生产工作台。

工作流固定为：

\`故事导入 → 当前集剧本 → 风格设置 → 角色/场景/道具 → 分镜规划 → 单镜头提示词 → 待审核视频 → 版本管理\`

本阶段仍以浏览器本地项目为主，不新增云端项目管理和多人协作。

## 与截图流程的对应关系

| 截图流程 | 漫剧助手实现 | 当前基础 |
| --- | --- | --- |
| 系列和集数列表 | 节点内章节列表、当前集切换 | \`storyboardChapters\` |
| 当前集剧本 | 原文、事实抽取、剧作总纲、事实锁定 | \`storyboardSourceBeats\`、\`storyboardDramaturgyPlan\` |
| 风格设置 | 比例、画风、光线、镜头和声音默认值 | 视频设置、\`storyboardAssetStyle\` |
| 角色/场景/道具 | 资产识别、提示词编辑、上传、生成、多视图 | \`storyboardAssets\` |
| 分镜规划 | 分镜表、场景卡、事实 ID、动态/静态镜头 | \`StoryboardShotPlan\` |
| 单镜头制作 | 资产绑定、首帧/尾帧、视频提示词、预览和版本 | 待审核视频节点、尾帧连续性 |

## 本阶段必须完成

1. Script 节点显示名和入口改为“漫剧助手”，底层继续复用现有 Script。
2. 一个节点支持多集文本和当前集切换，只为当前集准备资产和提示词。
3. 原文事实、剧作总纲、场景卡可以逐条审核和锁定。
4. 风格配置被资产、分镜和视频提示词继承。
5. 角色、场景、道具使用稳定 \`assetId\` 绑定，不依靠名称模糊匹配。
6. 每个镜头绑定来源事实、主要可见事实、地点、人物时期和资产。
7. 动态镜头输出从 0 秒连续到结束的四段式 \`videoMotionPrompt\`。
8. 失败按镜头隔离，只重试失败项，成功项不被覆盖。
9. 保留提示词版本、待审核视频节点、视频结果节点和尾帧引用。
10. 上游事实、风格或资产变化时，下游标记为“需要重新审核”，不静默覆盖。

## 核心数据契约

### 事实

继续使用 \`StoryboardSourceBeat\`，补充或等价实现：

- \`reviewStatus\`: \`draft | approved | rejected\`
- \`evidence\`: 原文位置或片段索引
- \`userEdited\`: 是否被用户修改

事实锁定后，分镜只能引用事实 ID，不得重新创造人物、关系、地点、对白和结局。

### 场景卡

每个 \`StoryboardShotPlan\` 必须具备：

- 目标 \`goal\`
- 失败代价 \`stakes\`
- 阻力 \`obstacle\`
- 人物策略 \`tactic\`
- 2-4 个因果动作 \`actionBeats\`
- 阻力反作用 \`obstacleReaction\`
- 动作转折 \`turningAction\`
- 可见结果 \`result\`
- 起始/结束状态 \`startState\`、\`endState\`
- 价值变化 \`valueShift\`
- 来源事实 \`sourceBeatIds\`

缺少核心字段时，镜头不能进入视频生成。

### 资产和提示词

资产必须区分识别、审核、生成和使用状态；镜头绑定保存 \`assetId\`。

每个镜头保存：

- \`storyboardPrompt\`
- \`videoMotionPrompt\`
- \`assetMentions\`
- \`assetMentionLinks\`
- \`promptSource\`
- \`promptVersion\`
- \`promptReviewStatus\`
- \`promptValidationErrors\`

最终视频只允许使用当前确认版本。

## 分阶段执行

### P0：节点身份和状态

在节点注册、创建菜单和弹窗标题中显示“漫剧助手”；保留旧 Script 数据；统一显示“剧本审核、资产审核、分镜提示词审核”。

主要文件：\`web/src/constant/canvas.ts\`、\`web/src/lib/canvas/node-registry.ts\`、\`web/src/components/canvas/canvas-script-node-dialog.tsx\`、\`web/src/types/canvas.ts\`。

完成标准：新建节点可打开漫剧助手，旧 Script 可继续打开。

### P1：系列和章节

增加多集文本/Markdown/CSV/截图导入；显示章节状态和当前集；切换当前集时只加载当前集数据；章节代理节点只保存引用，不复制资产和提示词；未确认当前集时不自动生成后续集资产。

完成标准：导入 1-14 集后，只为第 14 集进入后续流程。

### P2：事实和剧作总纲审核

展示原文片段、事实 ID、人物、地点、时间和事件；支持逐条通过、拒绝、编辑和锁定；剧作总纲字段显示事实引用；事实变化使受影响镜头失效并保留历史版本。

完成标准：任意镜头和提示词都能回溯到事实 ID。

### P3：风格圣经

增加比例、画风、色彩、光线、镜头语言和声音默认值；保存风格版本和锁定状态；下游继承风格版本；修改风格只标记下游重新审核。

完成标准：同一集的资产、首帧和视频提示词使用同一风格版本。

### P4：资产库

按角色、场景、道具分栏；角色支持年龄/时期、服装、身份和参考图；场景支持锁定图和多视图；详情页显示 AI 提示词、用户编辑、生成、上传和版本；必需资产未准备完成时禁止视频生成。

主要文件：\`web/src/components/canvas/canvas-script-node-dialog.tsx\`、\`web/src/lib/canvas/storyboard-asset-prompt.ts\`、\`web/src/types/canvas.ts\`。

完成标准：第 14 集的资产可以逐项审核，单个失败不影响其他资产。

### P5：场景卡和分镜

分镜卡显示来源事实、场景卡、资产和动态/静态状态；每镜只允许一个主要可见事实、一个地点和一个人物时期；增加审核、锁定、复制、拆分和单镜重规划。

完成标准：每镜都能回答“谁在什么地方，为了什么目标，做了什么动作，受到什么阻力，结果是什么”。

### P6：单镜头视频工作区

显示图片提示词、视频运动提示词、设置、参考资产和版本；自动绑定实际使用资产和上一镜尾帧；先创建待审核视频节点，确认后提交任务；结果保留多个版本；失败只重试当前镜头。

完成标准：一个镜头内可完成审核、修改、生成、查看版本和选择尾帧。

### P7：一致性和回归

增加事实、人物时期、地点、资产和动作链校验；保存规划/资产/提示词/视频 checkpoint；批量任务逐项隔离失败；用固定集数样本回归，不以“任务成功”代替“剧情正确”。

完成标准：修改一个事实、资产或风格后，系统能准确指出受影响镜头。

## 工作量估算

按一名熟悉当前代码的开发者估算，不含模型费用和大规模视觉回归：

| 阶段 | 估算 |
| --- | ---: |
| P0 节点身份和状态 | 2-3 天 |
| P1 系列和章节 | 4-7 天 |
| P2 事实和剧作总纲 | 4-6 天 |
| P3 风格圣经 | 3-5 天 |
| P4 资产库 | 6-9 天 |
| P5 场景卡和分镜 | 6-10 天 |
| P6 单镜头视频工作区 | 5-8 天 |
| P7 校验和回归 | 5-8 天 |
| **合计** | **35-56 个开发日，约 7-11 周** |

可用 MVP 只做 P0、P2、P4、P5、P6 的最小版本，约 **18-28 个开发日**。它能覆盖截图主要流程，但不包含完整系列管理、丰富版本历史和全部回归保护。

## 推荐顺序

不要机械按截图顺序开发，按风险顺序执行：

1. P0：确认节点身份和状态。
2. P2：先锁定事实和剧作总纲，解决剧情偏离。
3. P5：补齐场景卡和动作链。
4. P4：让资产按 ID 绑定。
5. P6：接入提示词和视频工作区。
6. P3：补齐风格继承。
7. P1：完善多集系列工作区。
8. P7：固定样本回归。

每阶段必须留下：变更文件、metadata 字段、用户操作路径、成功/失败/取消/重试证据、待人工验证项和固定样本截图。

## 第一批代码任务

下一次开始改代码时只做四项：

1. Script 节点显示名切换为“漫剧助手”，保留内部类型。
2. 为 \`StoryboardSourceBeat\` 增加事实审核状态和证据位置。
3. 为 \`StoryboardShotPlan\` 增加场景卡完成状态和校验错误。
4. 在三步弹窗增加“事实审核”和“场景卡审核”入口。

这四项完成并用一集样本验证后，再继续资产库和视频工作区。

## 结论

单开一个 Script 节点并命名为“漫剧助手”可行，也是当前风险最低的方案。不要复制新的生成系统，而是把现有 Script 产品化。真正的工作量来自事实锁定、资产 ID 绑定、场景卡、提示词版本、下游失效和逐项恢复；只搬页面不会解决剧情偏离。
