## 今天完成的主要事项

### 1. 新增沧元算力渠道格式

- 配置弹窗的渠道调用格式新增“沧元算力”。
- 默认 Base URL 为 `https://ai.cangyuansuanli.cn`。
- 保留原有 OpenAI / Gemini / 方舟 Ark 逻辑，不把沧元算力硬塞进 Ark Seedance 分支。
- 仍使用现有“拉取模型”按钮读取 `/v1/models`。

### 2. 模型能力分类补齐

- `omni` 会被归类为视频模型。
- `gemini-banana-*` 会被归类为图像模型。
- 原有 `seedance`、`sora`、`grok-video`、`flux`、`gpt-image` 等分类继续保留。

### 3. 图像生成适配

- 沧元算力图像渠道走 `POST /v1/images/generations`。
- 文生图和 JSON 图生图都走同一入口。
- 同步结果从 `data[].url` 读取。
- 异步结果会轮询 `GET /v1/images/generations/{task_id}`。
- 图生图参考图优先传 `image` / `images`，局部编辑传 `mask`。

### 4. 视频生成适配

- 沧元算力视频渠道走 `POST /v1/videos`。
- 轮询走 `GET /v1/videos/{task_id}`。
- 完成后优先读取 `video_url`，并兼容 `video.url`、`raw_data.video_url`、`data.video_url`、`data.url`；没有时再尝试 `/v1/videos/{task_id}/content`。
- 轮询间隔为 5 秒。
- 轮询响应会读取 `progress` 并用于节点真实百分比显示，失败时尽量展示 `error.message` / `error_code`。
- 参考视频或参考音频必须同时提供至少 1 张主参考图，符合沧元算力文档要求。
- 沧元算力下的 `seedance-2.0-*` 不再误走方舟 Ark 的 `/contents/generations/tasks`。

### 5. 单模型 API 文档补读

- 已补读图二“单模型 API 说明”区域的数据源：`GET https://ai.cangyuansuanli.cn/api/pricing` 返回的 `api_doc` 字段，与模型广场“查看文档”弹窗一致。
- 本次覆盖的视频模型：`seedance-2.0`、`seedance-2.0-fast`、`seedance-2.0-1080p`、`seedance-2.0-480p`、`seedance-2.0-4k`、`seedance-2.0-720p`、`seedance-2.0-fast-480p`、`seedance-2.0-fast-720p`、`seedance-2.0-mini-480p`、`seedance-2.0-mini-720p`、`omni-fast`、`omni-fast-no-water`、`omni-v2v`、`omni-v2v-no-water`、`sora2`、`grok-video`、`grok-video-1.5`。
- 本次覆盖的图像模型：`flux-pro-2`、`gemini-banana-2.0-1/2k`、`gemini-banana-2.0-4k`、`gemini-banana-flash-lite`、`gemini-banana-pro-1/2k`、`gemini-banana-pro-4k`、`gpt-image-2`、`gpt-image-2-2k`、`gpt-image-2-4k`。
- Seedance 2.0 系列统一走 `/v1/videos`、`/v1/videos/{task_id}`、可选 `/content`；分辨率/价格/快慢不同，但核心字段一致：`prompt`、`aspect_ratio`、`duration`、`image_url`、`reference_images`、`reference_videos`、`reference_audios`、`first_image_url`、`last_image_url`。
- Omni 系列走 `/v1/videos` 和 `/v1/videos/{task_id}`；文生/图生支持 `image_url`、多图 `input_reference`、首尾帧 `first_image_url` / `last_image_url`，V2V 使用 `video_url`。
- 文档中 `sora2` 的价格数据源里对应 `openai-sora2`，接口仍是 `/v1/videos` 和 `/v1/videos/{task_id}`，完成结果可能在 `video.url` 或 `raw_data.video_url`。
- Grok 系列不是 `/v1/videos`，文档写的是 `POST /v1/video/generations` 和 `GET /v1/video/generations/{task_id}`；本次已新增 Grok 分支，`grok-video` 支持文生、图生、多参考图和 `video_url` 视频编辑，`grok-video-1.5` 必须且只能单图参考。
- 图像模型文档统一支持 `/v1/images/generations` 的同步/异步模式，异步结果轮询后从 `data[].url` 取图；Banana / GPT Image / Flux 的核心差异主要在模型名、尺寸、质量、是否推荐同步以及是否支持参考图。

### 6. 模型价格显示

- 新增沧元算力价格读取服务，模型选择器会按渠道 Base URL 推导并缓存 `/api/pricing`，读取失败时保持原选择器逻辑不变。
- 沧元算力渠道的模型下拉项会在模型名后显示价格；`sora2` 会兼容价格数据源中的 `openai-sora2`。
- 视频工作台、画布配置节点、视频节点提示面板和最终提示词弹窗会把当前视频秒数传给模型选择器，按秒计费模型显示估算金额，按条/按次/按张计费模型显示单价。

### 7. 视频模型分辨率与参数分辨率联动

- 已识别 `seedance-2.0-1080p`、`seedance-2.0-720p`、`seedance-2.0-480p`、`seedance-2.0-4k` 等模型名里的固定分辨率档位。
- 在视频工作台、画布配置节点、视频节点提示面板和最终提示词弹窗里，选择带固定档位的模型会同步 `vquality`，设置按钮和面板显示也以模型档位为准。
- 在视频设置面板点击同系列可用档位时，会自动切换到对应模型，例如从 `seedance-2.0-1080p` 点 `720p` 会优先切到 `seedance-2.0-720p`，价格随模型刷新。
- 无固定分辨率档位的 Seedance 模型仍保留手动分辨率选择；生成请求兜底归一化仍以模型档位优先，避免旧节点残留参数造成冲突。

## 如果测试失败优先看

- 401 / 403：检查 API Key、账户权限和模型权限。
- 拉取模型为空：先直接验证 `GET https://ai.cangyuansuanli.cn/v1/models` 是否对当前 Key 开放。
- 图像无返回：检查响应里是否是异步任务 ID；如果是，应看轮询接口是否返回 `completed` 和 `data[].url`。
- 视频超时：确认任务状态是否停在 `queued` / `in_progress`，以及是否触发内容安全拦截。
- Seedance 相关参数错误：优先看是否传了不支持的比例、时长、参考视频/音频，或缺少主参考图。
