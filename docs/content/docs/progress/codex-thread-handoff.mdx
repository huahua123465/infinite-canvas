# Codex 换线程交接模板

当同一个 Codex 对话连续使用很久、上下文越来越大、单次请求已经稳定到 10 万 token 以上时，建议主动换一个新对话继续。

这样做的目的不是中断工作，而是把当前任务压缩成一份短摘要，再让新对话基于代码和摘要继续执行，减少重复携带的历史聊天。

## 适合换线程的情况

- 同一个任务已经连续聊了 2 到 3 天。
- 当前对话里已经贴过很多日志、截图、长代码或文档。
- 请求延迟明显变高，单次输入 token 持续偏大。
- 任务主题已经变化，例如从方案讨论切到代码实现，或从 A 功能切到 B 功能。

## 推荐流程

1. 在旧对话里让 Codex 生成交接摘要。
2. 新开一个对话。
3. 把交接摘要贴进去。
4. 明确要求先读取相关文件，再继续实现。

## 旧对话总结提示词

把下面这段发给当前对话：

```text
请总结当前任务，输出给新对话续接用的交接摘要，控制在 300~500 字，包含：
1. 目标
2. 已完成
3. 未完成
4. 关键文件
5. 当前约束
6. 下一步建议

要求：
- 面向 infinite-canvas 项目
- 遵循 AGENTS.md
- 不要回顾无关讨论
- 尽量写成可直接复制给新对话的格式
```

## 新对话续接模板

新开对话后，直接贴下面这段，再接上旧对话生成的摘要：

```text
基于下面交接摘要继续 infinite-canvas 当前任务，不需要回顾旧对话，先读取相关文件再动手。

当前约束：
- 遵循 AGENTS.md
- 不跑构建
- 页面文案中文

交接摘要：
```

然后把旧对话输出的摘要粘贴到 `交接摘要：` 后面。

## 极简可复制模板

如果你想自己手写摘要，也可以直接用下面这份：

```text
继续 infinite-canvas 的 XXX 任务。

已完成：
- ...
- ...

当前约束：
- 遵循 AGENTS.md
- 不跑构建
- 页面文案中文

相关文件：
- web/src/...
- docs/content/docs/...

下一步：
- ...
```

## 建议

- 一个对话尽量只处理一个主任务。
- 长日志、长 JSON、整篇文档尽量少直接粘贴到聊天里，优先告诉 Codex 文件路径。
- 稳定规则尽量沉淀到项目文档，不要长期依赖聊天历史充当知识库。
- 如果只是接着做代码，交接摘要通常不需要超过 500 字。

## 说明

新对话不会自动继承旧对话的完整聊天记录，但会继续读取当前工作区代码、文档和你贴进去的交接摘要，所以摘要越聚焦，后续成本越低。
