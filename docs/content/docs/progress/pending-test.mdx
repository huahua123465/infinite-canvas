# 待测试

- 分镜角色资产统一设定图：脚本节点第二步“准备资产”识别角色时，同一人物的不同年龄/时期状态应拆成独立角色资产，例如“白秋妹·年轻时期”“白秋妹·成年时期”，不应把多个年龄阶段塞进同一张角色图；角色资产图生成应统一为横向 16:9 单角色设定图，包含正面全身主视图和同一年龄状态的侧面/背面/半身/表情参考，背景简洁且无文字、Logo、水印、多人合照或成长时间线；第三步合成提示词应按镜头内容引用对应年龄状态的资产。
- 3D 导演台完整入口：主导航应新增“3D导演台”入口，点击后跳转到 `/director-desk` 并全屏打开完整 3D 导演台；页面应保留原有导演视角/机位视角、角色、机位、模型导入、全景、截图和本地场景持久化能力，关闭按钮应返回画布库。
- 分镜视频多版本收纳：同一待审核视频节点多次生成后，画布外层只应显示当前最新视频，最新视频应轻微覆盖在对应镜头卡片上方，不再向右侧连续铺开遮挡其他镜头；镜头卡片底部应显示“所有视频”入口，点击后可在弹窗中查看该镜头全部历史视频版本，并标记当前最新版本。
- 分镜场景多角度批量生成：脚本节点第二步“准备资产”的“场景”标题旁应显示“一键生成全部多角度锁定图”入口；点击后只对还没有锁定图的场景生效，并按 3 张一组并发生成；生成中的单个场景卡片应显示“暂停生成”并可单独停止；只有点击批量生成后，标题旁入口才切换为“一键暂停全部”，单个场景生成时标题旁入口仍保持一键生成状态；顶部“暂停生成”也能停止全部，已完成的锁定图应保留并继续作为后续视频的“场景锁定”参考。
- 分镜视频场景一致性：脚本节点第二步的场景资产卡片应显示“生成多角度锁定图”入口；点击后生成一张 2x3 的同场景多角度 sheet，而不是在画布右侧铺开多张角度节点。后续创建待审核视频节点时，如果该场景已有多角度锁定图，应自动作为“场景锁定”参考图补入参考数组；最终生成提示词应说明该 sheet 只用于理解空间关系，不要生成分屏、拼图或多宫格画面，并继续约束场景空间结构、门窗位置、材质、道具摆放、光线方向和单一主运镜。
- 分镜场景锁定图预览：脚本节点第二步的场景资产卡片中，已生成的多角度锁定图应支持点击放大查看；大预览弹窗应完整显示图片，不裁切，并保留“重做多角度锁定图”入口，便于检查同一场景不同机位的一致性。
- 分镜场景锁定图无文字标注：重做或批量生成多角度锁定图后，2x3 拼版里不应出现 `MAIN VIEW`、`FRONT VIEW`、`LEFT SIDE VIEW`、`RIGHT SIDE VIEW`、`TOP-DOWN VIEW`、`REAR VIEW` 等左下角视角标签，也不应出现字幕、说明字、Logo 或水印。
- 分镜场景锁定图横向比例：重做或批量生成多角度锁定图后，图片整体应是横向 16:9 宽画布，按 3 列 x 2 行铺满卡片，效果应接近“湖南湘西县城广场”多角度图，不应生成竖版长图、窄图、黑边或大面积留白。
- 分镜角色声音一致性：脚本节点第二步的角色资产卡片应显示“角色声音”区域，可根据当前角色设定生成声音提示词和试听音频；生成后的声音样本应能在角色卡片和右侧编辑面板中播放，后续创建/刷新待审核视频节点时，引用该角色的镜头应自动带入角色声音参考，并在最终生成提示词中追加声音一致性要求。当前机制用于提高视频模型内置声音的一致性，若要完全固定多镜头音频，仍建议后续使用关闭视频原生声音并统一后期混音的流程。
- 分镜角色声音试听质量：点击“生成角色声音”或“重做角色声音”时，应根据角色名称、描述和提示词推导年龄感、性别感、父母/老人等角色类型，生成更长的中文试听台词，并记录本次使用的 voice、speed、instructions 和试听台词；默认 OpenAI TTS 声线应比固定 `alloy` 更贴近角色，火山 OpenSpeech 场景仍应保留用户填写的 speaker ID。
- 分镜角色声音剧本关联：角色编辑面板应允许为单个角色填写声音 / speaker ID 和试听台词；生成角色声音时，手填试听台词优先，其次应从分镜表“对白旁白”列中提取提到该角色的台词，避免所有角色都朗读同一句通用样本。使用火山 OpenSpeech 时，如果角色没有单独 speaker，应提示当前会沿用全局 speaker，无法仅靠角色描述自动改变男女声。
- 火山语音合成接入：音频生成应支持火山 OpenSpeech TTS HTTP 接口；当音频模型为 `seed-tts-*` / `seed-icl-*` 或 Base URL 指向 `openspeech.bytedance.com` 时，应使用 `X-Api-Key` 和 `X-Api-Resource-Id` 调用 `/api/v3/tts/unidirectional`，并允许“默认音频声音”填写火山 speaker ID，例如 `zh_female_..._bigtts`。
- 火山角色音色校验：火山语音合成应把 `req_params.speaker` 作为实际音色来源，不再把空值回退为 OpenAI 默认 `alloy`；如果角色和全局配置都没有有效火山 speaker，应直接提示填写 speaker ID，避免女角色生成成默认男声或所有角色共用同一个错误音色。
- 火山角色音色选择：角色声音编辑区应支持手填 speaker ID、从内置火山音色候选中搜索选择，并可按角色文本自动填入推荐 speaker；未手动选择时生成试听应自动使用推荐音色并写回角色，便于试听后继续调整。
- 火山语音错误排查：火山 TTS 失败时应尽量展示接口返回的原始错误码、错误信息和 logid；如果用户误把控制台实例名 `TTS-SeedTTS2...` 填到音频模型里，应自动归一为接口要求的 `seed-tts-2.0`。
- 角色音色渠道隔离：角色上保存的火山 speaker ID 只应在火山 OpenSpeech 音频模型下生效；使用 OpenAI TTS 时应继续映射为 OpenAI 支持的 `alloy`、`coral`、`nova`、`onyx` 等 voice，避免把火山 speaker 传给 OpenAI 导致 `field_invalid`。
- 火山音频自动路由：当本次音色是火山 speaker 但当前默认音频模型仍解析到 OpenAI 等非火山渠道时，应在已配置模型中自动查找 `openspeech.bytedance.com` / `seed-tts-*` 音频渠道发起请求，降低只新增渠道但未切换默认音频模型导致的误路由。
- 火山 speaker 兜底：已进入火山 TTS 请求后，如果上层没有正确传入角色 speaker，应根据音频指令和试听台词自动推荐一个火山 speaker，避免误用 OpenAI 默认 voice 后直接中断生成。
- 角色声音模型选择：脚本节点右侧角色声音编辑区应显示当前默认音频模型，并支持直接切换音频模型；切换后生成角色试听应使用新的默认音频模型，减少用户不清楚当前走 OpenAI 还是火山 TTS 的问题。
- 火山网络错误提示：火山 TTS 请求没有 HTTP 响应时，应显示 Network Error/CORS 方向的提示，避免把浏览器直连 OpenSpeech 被拦截误判成 speaker 或额度问题。
- 火山语音本地转发：火山 OpenSpeech TTS 应优先通过本地 Infinite Canvas Agent 代理请求；本地 Vite 开发环境应提供 `/api/v3/tts` 同源代理，避免浏览器直连 `openspeech.bytedance.com` 时被 CORS 或本机网络策略拦截。
- 火山语音旧版鉴权：音频渠道 API Key 字段应支持填写 `APP ID|Access Token` 或包含 `appId` / `accessToken` 的 JSON，用于旧版控制台 OpenSpeech 鉴权；本地 Agent 代理也应按同样规则转发对应请求头。
- 火山语音音频解析：火山 OpenSpeech V3 HTTP Chunked 返回成功后，应兼容二进制协议帧和逐行 JSON/base64 音频片段，把真实音频 payload 拼接后再保存，避免浏览器音频控件显示 `0:00 / 0:00` 且无法读取 duration。
- 角色声音模型选择稳定性：脚本节点右侧角色声音区的音频模型选择应改用 Ant Design Select，避免 Radix Select 在当前 React 运行时中反复更新 ref 导致 `Maximum update depth exceeded`。
- Seedance 第三步合成提示词：合成 `storyboardPrompt` / `videoMotionPrompt` 时应通过本地 Canvas Agent 运行时读取 `seedance-2.0-5.3.0/seedance-2.0-5.3.0` 技能包，并吸收 `seedance-20` 的导演公式、模式判断、动作/运镜约束和保守重试自检；Agent 未连接时回退到内置规则。合成结果应更明确区分首帧静态画面和视频运动导演指令，并根据第二步资产清单收口 `assetMentions`，减少虚构资产、过度引用资产、运镜冲突和空泛堆词。
- 分镜视频节点：生成失败时应在节点主体区域清晰展示失败原因；放大节点后提示词、错误信息、参考资产和底部操作区的空间分配应更均衡。
- 脚本节点资产侧栏：视频或提示词相关动作结束/失败后，已选资产的“重新生成图片”按钮不应被无关状态置灰；仅资产生成中或批量资产动作中才应锁定。
- Seedance 最终提示词：当模型把 `@资产名` 和后续描述粘连在一起时，应优先按已有资产名前缀绑定参考图；后续合成提示词应要求资产名后用空格或标点隔开。
- 分镜视频多版本：待审核视频节点点击“生成视频”后应保留为可继续编辑的提示词节点，并在右侧新增独立视频结果节点；多次修改提示词生成时，旧视频和新视频应同时保留在画布中，下一镜首帧默认跟随上一镜最新成功版本。
- 分镜视频连续性：下一镜接入上一镜尾帧时，待审核节点和最终提示词弹窗都应明确显示首帧来源，例如“首帧来自第 1 镜 v1 尾帧”；未接入时应显示“未接入上一镜尾帧”。
- 分镜视频最终提示词弹窗：视频生成设置和最终提示词应自动保存到当前镜头，修改后显示“已自动保存”，关闭后再次打开仍保持上次设置。
- 分镜视频最终提示词资产选择：最终生成提示词弹窗应直接显示当前剧本资产、场景锁定图和我的素材候选；点击资产卡片或在句子中间输入 / 点击 `@` 后从下拉菜单选择资产时，应自动插入 `@资产名`、显示缩略图，并立即保存引用绑定关系，不需要手动输入资产名称；修改提示词中间内容时，光标不应因为自动保存跳到文本末尾。
- 分镜视频子弹窗外部点击关闭：最终生成提示词、参考资产编辑和所有视频弹窗应支持点击弹窗外部区域关闭；在弹窗内部输入、滚动、点击按钮、选择素材、打开模型/设置下拉或使用 `@` 资产菜单时不应误关闭。
- 分镜视频连续性编辑：编辑参考时应能从上一镜多个视频版本的尾帧中手动选择一个设为首帧，也能移除当前尾帧首帧；保存后最终提示词里的连续性要求同步更新。
- 分镜视频尾帧回填：打开已有项目时，旧的分镜视频结果如果还没有尾帧 metadata，应自动从视频中提取尾帧并出现在下一镜“连续性首帧”候选中。
- 分镜视频旧结果兼容：旧项目中已生成的视频即使缺少新版分镜结果字段，只要仍连接在上一镜待审核视频节点后，也应被识别为上一镜结果并参与尾帧回填和下一镜首帧候选。
- 分镜视频尾帧识别兜底：旧视频结果即使没有新版字段或连线，只要位于同一个视频工作区且位置靠近上一镜待审核视频节点，也应尝试归属上一镜、自动截取尾帧，并出现在下一镜“连续性首帧”候选中。
- 脚本节点画幅设置：脚本节点整体提示词中的“视频生成设置/比例”支持 `16:9`、`9:16`、`3:4`、`4:3`，后续资产图、分镜图、待审核视频节点和视频生成请求都应使用该比例；普通视频接口不应再把 `3:4` 近似成 `9:16` 或把 `4:3` 近似成 `16:9`。
- 脚本节点操作栏：大弹窗第二步“准备资产”顶部应显示识别/批量生成资产按钮，且不显示“批量合成提示词”；第三步“合成提示词”顶部才显示批量合成提示词和视频完成数，且不显示第二步资产按钮。
- 脚本节点安全改写：第二步资产提示词、资产生图、第三步合成提示词、分镜图和待审核视频提示词应自动规避“未成年人、伤残、血腥、受害、极端困境”等高风险直白表述，改用年轻角色、行动不便、身形单薄、朴素旧衣、生活艰难等中性视觉表达；安全系统拒绝时应显示中文说明并保留 request id。
- 配置与用户偏好：恢复方舟 Ark 调用格式选项，渠道调用格式应显示 OpenAI / Gemini / 方舟 Ark；选择方舟 Ark 时默认 Base URL 应为 `https://ark.cn-beijing.volces.com/api/v3`，模型列表支持填写 Seedance 模型 ID 或 Endpoint ID（`ep-xxxx`），且方舟 Endpoint ID 可进入视频模型可选项。
- 脚本节点视频设置：在脚本节点整体提示词中写入“视频生成设置/视频设置/video:”参数块时，应能解析分辨率、比例/尺寸、时长、生成声音和水印，自动同步到后续单镜头/批量视频草稿；重新搭建视频工作区时，未单独改过的旧草稿应跟随脚本默认设置刷新，已手动修改的待审核视频节点设置优先于脚本默认设置。
- Vite 融合迁移：新增 `custom/jt-vite-merge` 迁移分支，以官方 Vite + React Router 结构为底座迁入 custom/jt 的画布短剧工作流，需验证首页、画布项目页和基础文本/图片/配置/视频/音频节点仍可正常创建、连接、生成和重试。
- 脚本节点：迁入 Script Node、分镜大表格、TXT/MD/CSV/截图导入、连接剧本文本生成分镜、手动增删改镜头和 120 行上限，需重点验证三步流程“确认镜头 / 准备资产 / 合成提示词”以及第 9 列“分镜画面提示词”命名。
- 脚本节点：连接剧本文本生成分镜时，脚本节点自身的整体提示词会作为“整体要求/导演提示词”保留并传入后续流程，需验证第一人称 POV、皮克斯 3D 等自定义要求能贯穿确认镜头、准备资产、合成提示词和视频提示词。
- 分镜资产准备：迁入角色/场景/道具识别、阶段型进度条、精简分镜表请求、资产卡片编辑、上传资产图、单个/批量生成资产图和暂停生成，需验证不会把第 9 列提示词发送给资产识别。
- 角色资产风格：本次移除官方素材/虚拟演员 ID 绑定入口，角色资产统一按非写实虚拟角色、2.5D、动画或漫画质感生成；需验证第二步资产卡片、普通图片节点和第三步合成提示词中不再出现官方素材 ID 输入、官方脸标记或素材 URI 绑定提示。
- Seedance 视频提示词：迁入第三步 `storyboardPrompt` / `videoMotionPrompt` 双提示词、@ 资产引用解析高亮、最终视频提示词确认与可编辑入口，需验证单镜头和批量视频生成都优先使用 `videoMotionPrompt`，不退回第一步画面提示词。
- Seedance 视频审核：单镜头“生成视频”改为先创建待审核视频节点并打开最终提示词确认页；需验证普通视频和分镜视频参考图只使用已生成/上传的资产图、首帧和尾帧，不再插入官方素材引用。
- Seedance 提示词技能：恢复 `.agents/skills/seedance-video-prompting`，需确认 Codex 后续生成/审查 Seedance 视频提示词时能继续读取该 skill。
- 视频工作区与连续性：迁入待审核视频节点、参考资产编辑、首帧/参考/尾帧角色、非写实角色参考图提醒、视频阶段式进度条、成功后提取尾帧并传给下一镜首帧，需验证节点显示“已使用上一镜尾帧作为首帧”。
- Seedance REST 接口：保留 custom/jt 的官方接口修正，需用方舟环境验证 `POST /contents/generations/tasks`、`GET /contents/generations/tasks/{id}`、`content` 数组、`aspect_ratio`、`generate_audio`、大写 `480P/720P/1080P`、30 秒轮询、9 张参考图上限和 400 原始错误展示。
