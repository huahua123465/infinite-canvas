# 待测试

- 官方 v0.10 标准 JSON 提示词来源：配置与用户偏好的“提示词来源”应显示 Banana Prompt Quicker 等六个内置来源，并允许通过名称、JSON URL、可选主页新增自定义来源；内置来源不可编辑或删除。每个来源应显示提示词数量、正常/失败/未同步状态和上次成功时间；单个来源更新失败后继续展示上次成功缓存，不得清空已有提示词或阻止其他来源更新。定时拉取只更新到期、失败或配置已变化的来源。
- 官方 v0.10 提示词中心与画布侧栏：提示词中心应采用左侧分类/标签、右侧搜索与内容的双栏布局，搜索输入具备防抖且覆盖标题、正文、描述、分类和标签；不同来源存在相同提示词 ID 时卡片不得冲突。详情应展示描述、封面和多张参考图。画布侧栏输入关键词后应自动加载并搜索所有启用来源，未手工展开的来源也能返回结果；插入画布的文本节点应保留提示词标题。
- 官方 v0.10 Agent 与画布交互：Agent 对话中用户消息应以右侧气泡显示，AI 消息保持左侧流式内容；用户向上查看历史消息时新内容不得强制抢回底部，并应出现可点击的“滚动到底部”按钮。上传图片附件后应创建真实画布图片节点并可继续连接生成流程；图片节点元数据应与普通上传图片一致。画布节点生成完成后提示词输入应继续保留。

- 沧元视频模型价格展示：模型下拉中的按秒计费模型应同时显示单价（如 `¥0.525/秒`）和按当前视频时长估算的总价（如 `约¥7.88`）；按次计费模型继续显示 `¥X/次`，切换视频时长后总价应同步更新。
- ToonFlow 沧元供应商导入文件：上传 `Toonflow-app-master/cangyuan-vendor.ts` 后，应出现独立的“沧元算力 API”供应商；分别填写文本、图片、视频三个 API Key 后，三类请求必须使用对应 Key。文本模型调用 OpenAI 兼容接口，图片模型走 `/v1/images/generations` / `/v1/images/edits`，视频模型走 `/v1/videos` 并轮询 `/v1/videos/{task_id}`。该配置与 Infinite Canvas 画布渠道彼此独立，视频参考素材和不同模型限制仍需用真实任务验证。

- 画布文本节点与分镜最终提示词的 `@` 资产菜单：在长文本中间输入 `@` 后，候选菜单应贴近当前光标显示，不得固定漂到输入框外或遮挡无关正文；输入区滚动、窗口尺寸变化和弹窗边界变化后仍应保持在可视区域内，鼠标点击候选项应能正常插入引用，键盘上下键和回车选择仍可用。
- 画布资源引用范围：文本/提示词节点输入 `@` 时只显示从左侧直接或经配置节点连入的图片、视频、音频和文本资源，未连线素材不得显示为可提交候选；候选顺序必须与最终请求数组一致。浏览器刷新后仅保留 `storageKey` 的已连线图片资源也应出现在候选菜单并可点击插入。
- 画布连接方向与文本节点滚动：图片从左侧连入文本、或图片先连入配置节点再由配置节点连入目标节点时，输入 `@` 都应显示已连接图片；从节点左侧 target 端反向拖拽建立连接后也必须保存为“输入节点 → 目标节点”，目标节点的出线和历史生成结果不得被反向收集。长文本节点内容必须被限制在节点内部，超出部分通过内部滚动条查看，不得撑出节点覆盖底部工具栏。
- 提示词面板长文本与连接资产：打开画布节点下方提示词面板，长提示词不得把面板和底部操作栏撑出节点范围；输入区高度保持稳定并可在内部上下滚动。图片从左侧直接或经配置节点连入当前节点时，任意位置输入 `@` 都应显示对应图片缩略图候选。
- 提示词放大编辑器：点击节点右上角放大按钮后，长提示词应限制在中间编辑区域内上下滚动，底部模型、参数和生成按钮始终固定可见，不能被文本内容覆盖或顶出弹窗。
- 放大提示词编辑器的 `@` 菜单：在放大编辑器正文任意位置输入 `@`，候选资源菜单应显示在弹窗内容之上并可点击，不能被 `z-index` 遮罩层隐藏；选择后应插入对应图片缩略图标签。
- 提示词引用图片预览：在普通提示词面板、放大编辑器或配置节点组装器中点击 `@imageN` 图片缩略图后，图片预览及遮罩应完整显示在输入面板和 `@` 菜单之上，不得只露出面板两侧；关闭预览后应继续保留当前提示词和图片绑定。
- 沧元 Seedance Mini 参考图绑定：使用 `seedance-2.0-mini` 生成视频时，界面中的 `@图片1`、`@视频1`、`@音频1` 应转换为 API 文档要求的 `@image1`、`@video1`、`@audio1`；普通图片发送到 `reference_image_urls`，只有明确首帧或同时带参考视频/音频、受上游主图要求约束时才发送第 1 张到 `image_url`，生成结果应保持参考人物身份与外观。
- 沧元 Seedance 参考图自动绑定：画布仅通过连线提供参考图、而用户提示词未手写 `@图片N` 时，提交前应自动补齐 `@图片N`（视频/音频同理），并在最终 prompt 中显式列出已绑定素材；沧元请求仍须将其转换为 `@imageN/@videoN/@audioN`，验证生成结果是否按普通人物参考图保持身份与外观，同时不把普通图片直接复刻成视频首帧。
- 沧元 SD5 Seedance 参考图字段与绑定：`sd5-seedance-2.0` / `sd5-seedance-2.0-fast` 应使用 `reference_mode=media`、`images`、`reference_videos`、`reference_audios`，并把提示词中的 `@图片N/@视频N/@音频N` 转为上游要求的 `@imageN/@videoN/@audioN`；确认请求成功后再评估真人脸部一致性，区分字段/绑定错误与上游模型效果波动。
- 沧元 Seedance 提示词原生引用标签：视频提示词面板选择沧元 Seedance 模型时，`@` 菜单与已插入素材应直接显示 `imageN/videoN/audioN`，图片 chip 同时显示缩略图和 `@imageN`，已有 `@图片N/@视频N/@音频N` 自动改为 `@imageN/@videoN/@audioN` 并保存；其他渠道、图片生成和文本节点继续使用原有中文标签。
- 沧元 Seedance 请求组装一致性：配置节点即使没有手工输入 `@imageN/@videoN/@audioN`，所有真实入线素材也必须按同类型连线顺序加入参考数组；普通节点与配置节点中的内部引用、中文标签、API 标签和已连接素材文件名都应在最终请求中归一为同序的 `@imageN/@videoN/@audioN`。最终提示词顶部应列出数组标签、素材名和控制职责，其中图片锁定主体身份/脸部/发型/服装/画风，视频只参考动作与运镜，音频只参考声音与节奏。生成请求只沿当前节点入线收集素材，配置节点向外生成的旧图片、视频、音频和文本结果不得回流为下一次请求的参考素材；用一张人物图连续生成多个视频时，生成前确认应始终只显示该图片 1 张、参考视频 0 条。
- 视频生成连接资源一致性：视频节点生成时应使用与 `@` 候选菜单相同的仅沿入线收集的有序资源集合；图片从左侧直接或经配置节点连入、且仅保留本地 `storageKey` 时，也必须进入实际视频请求并按明确首帧或普通多模态参考图的角色发送。提示词是否手写 `@` 只决定绑定描述，不再决定素材是否提交。
- 普通视频连续生成多版本：已有成功视频再次点击“生成视频”时，应在当前视频右侧新增独立的视频生成节点，并复制上一版视频的原始入线；不得把上一版成片串成新节点的参考视频。使用同一张人物图连续生成多个视频时，每次请求都应保持原图片/文本/配置输入，上一版成功视频在新任务生成中或失败时仍保持可播放和成功状态；仅当原始入线本身就是视频素材时，才继续作为视频转视频参考。
- 沧元固定档位 Seedance 与本地媒体：`seedance-2.0-480p/720p/1080p/4k`、mini/fast 固定档位模型明确支持最多 9 张参考图；普通本地参考图应以 Data URI 通过 `reference_image_urls` 提交，明确首帧的单张本地图可使用 multipart `image`，明确首帧的多图请求使用 `image_url` + `reference_image_urls`，并以提示词中的 `@imageN` 保持顺序绑定。标准 Seedance 最多 4 张本地图，同样可按文档使用 Data URI JSON 多模态字段。标准与固定档位 Seedance 的参考视频/音频字段只接受公网 HTTPS URL，本地文件不得伪装成 Base64 放入 JSON。
- 沧元 Seedance 本地参考视频自动临时发布：连接本地参考视频后，生成流程应自动从 IndexedDB 读取视频，上传到默认临时中转并取得一小时有效的 HTTPS 直链，再把该地址放入 `reference_videos` 提交沧元；用户不需要配置上传接口、复制命令或回填 URL。任务完成或明确失败后应主动删除临时文件，浏览器关闭或网络中断时由一小时生命周期兜底；同一 `storageKey` 的有效临时地址可复用。临时发布失败、文件超过 100MB 或返回非 HTTPS 地址时不得创建付费视频任务。
- 沧元视频模型组装复核：模型广场当前 23 个 OpenAI Video 型号按单模型文档归并核对为标准/固定档位 Seedance、SD5、Veo、Sora、Omni 六类协议。Omni 文生/图生模型在 0–1 张参考图时应使用 JSON `image_url`，2–5 张时使用 multipart `input_reference`；Omni V2V 继续使用公网 JSON `video_url` 或本地 multipart `input_video`。固定档位 Seedance 参考图应执行单图 30MB、边长 300–4000px、宽高比 0.4–2.5，参考视频应执行边长 300–6000px、宽高比 0.4–2.5；标准版参考视频仍执行 720–2160px。固定档位不应显示或提交生成声音、水印参数。
- 沧元 Omni V2V：`omni-v2v` / `omni-v2v-no-water` 必须且只能提交 1 条源视频，不接受图片或音频，画幅只允许 16:9/9:16；公网视频使用 JSON `video_url`，本地视频使用 multipart `input_video`，本地源视频超过 5MB 时应在提交前阻止。生成前确认页显示的字段必须与实际传输方式一致。
- 视频生成前参考素材确认：点击生成后应先显示本次实际提交的模型、图片/视频/音频数量和上游参考字段；无参考素材时明确提示“纯文生视频”，用户确认后才提交任务。

- 沧元视频失败诊断与请求摘要：轮询返回顶层 `FAILURE` 或嵌套 `data.status=failed` 时应立即结束，不得继续等待到本地超时；失败信息应读取 `data.error`、`fail_reason`、`error_code` 和 `result_url`，只有平台返回 `GENERATION_FAILED` 且无细分原因时才显示“上游已接单但未返回具体原因”。任务节点应保存不含 URL、Base64 和提示词正文的请求摘要，包括实际模型、参数、提示词长度与 SHA-256、参考素材顺序/职责/类型/来源。

- Script 分镜生产契约门禁：第一步每个动态片段应生成明确的 `participants`（actor/patient）和 `typedActionBeats`（actor/action/patient/prop/result），婴儿或被照护者不得成为成人照护动作执行者；第三步提示词、资产自动补齐、待审核草稿、手工编辑和最终提交必须复用同一契约校验最终版本。场景、人物、道具和首尾帧职责必须与实际有序参考数组一致；安全兜底只要通过同一校验即可继续生成，不因来源标签单独硬阻断。概念片等非人物主题不得被强制要求主角人物弧线字段。

- 本地 Agent 面板源码完整性：打开首页或画布时不应再出现 `canvas-local-agent-panel.tsx` 的 Vite 红色错误遮罩；Agent 连接、对话、历史、日志、工具确认、停止任务和上传图片附件落画布功能应正常显示，并继续使用当前分支已有的图片节点元数据格式。

- ToonFlow 一键启动与画布入口：运行根目录 `start-web.bat` 时应在不阻断其他本地服务的前提下准备并启动 `Toonflow-app-master`；画布底部“3D导演台”旁应显示 ToonFlow 按钮，点击后通过已连接的本地 Canvas Agent 启动 ToonFlow，已运行时应恢复并聚焦现有窗口，不得重复创建多个 Electron 实例。未连接本地 Agent 或缺少 Node.js 24、项目目录时应显示明确错误。

- 官方 v0.9 画布侧栏与导出：左侧面板应支持展开/收起、220-480px 拖拽调宽和画布/资产/提示词库滑动切换；资产页可上传图片/视频、悬停插入或移除，画布页可多选节点导出压缩包，顶栏菜单可导出包含本地资源的当前画布。以上操作不得影响 Script、Workspace、分镜资产和已有浏览器本地项目。

- 官方插件与节点输入：HTML 1.2、Markdown/全景/便利贴/SVG 1.1 应显示正确版本和升级提示；全景可上传或用内置生图面板生成，HTML/全景可切换移动与交互，SVG 背景透明，Markdown 移动视角时不重复请求图片。节点名称仅在选中、悬停或编辑时出现，节点右上角不再显示“图片1/文本1”资源角标，提示词输入区无额外底色和边框；图片引用显示真实缩略图，编辑和最终请求仍保存 `@图片N`，不得退化为裸 `图片N`。

- 官方透明背景与本地 Agent：图像设置开启透明背景后，自定义模型脚本、普通 `/images/generations` 与 multipart `/images/edits` 应仅发送 `background=transparent`，默认关闭时不发送；沧元原有图生图 multipart 与引用绑定不得回退。本地 Agent 在多标签页中应按活动页执行工具并拒绝其他页伪造结果，共享 Codex 会话和运行状态保持同步，`generation_get_status` 能查询画布/生图/视频任务。

- 项目入口与目录精简：顶部导航、画布右键菜单和底部工具栏不再显示 Jellyfish，访问旧 `/jellyfish` 地址应进入未找到页面，`start-web.bat` 不再检查或启动 7788/8000 服务；`/director-desk` 仍应打开现有内置导演台并保留当前本地工程，仓库中不再包含 Jellyfish 和独立导演台重复源码。

- 沧元 `sd5-seedance-2.0` / `sd5-seedance-2.0-fast`：应按单模型文档通过 `POST /v1/videos` 提交，继续执行 1200 字符提示词上限、16:9/9:16 和 480p/720p；全能参考分别最多 9 图/3 视频/3 音频且三类合计不超过 12，纯参考视频或纯参考音频不应被错误要求补主参考图，但视频和音频必须使用公网 HTTPS URL。超限或本地媒体应在提交前阻止，任务创建后应能正常轮询并取回视频；参考视频单条 1-15 秒、总计不超过 45 秒的旧限制仍需用最小真实请求确认。

- 沧元 `seedance-2.0-mini-8s`：切换模型时应自动使用 720p、8 秒，设置面板只允许 480p/720p 和 4-8 秒；普通视频、画布视频与分镜视频提交 9-15 秒时都应在本地阻止，4-8 秒请求应按图片角色使用标准 Seedance 的可选 `image_url` / `reference_*` 字段创建和恢复任务。

- 沧元 Veo 3.1：`veo-3-1` / `veo-3-1-fast` 应只允许 4/6/8 秒、16:9/9:16、720p/1080p 和最多 2 张首尾帧参考图，并发送 `reference_mode=frame`；`veo-3-1-ref` 最多允许 3 张主体或素材参考图并发送 `reference_mode=image`。三种模型都应执行 1200 字符提示词和单图 10MB 上限，不得接受参考视频或参考音频，任务仍通过 `POST /v1/videos` 创建并按沧元任务 ID 轮询。

- 普通视频生成失败后点击“重新生成”时，应复用失败节点保存的原始提示词；即使上游文本、Composer 内容或连接的参考素材发生变化，重试请求中的提示词正文仍应与首次提交一致，同时仍能恢复原有参考素材。分镜视频应继续优先使用已保存的最终提示词。

- Script 合成提示词弹窗与视频最终提示词弹窗：编辑区不再重复显示整段高亮文本；脚本弹窗仍保留本镜头资产引用标签，视频确认页仍应保留最终提示词编辑、资产标签、自动保存和生成请求行为。

- 本地 Voicebox 音频渠道：根目录 `start-web.bat` 应作为唯一用户启动入口，在同一窗口列出并检查 Canvas Agent、音频分离、Voicebox 和 Web；Voicebox 未准备时应由该入口自动拉取固定的上游 `v0.5.0`、创建私有 Python 环境、安装官方依赖、构建 Web 并启动 `127.0.0.1:17493`，不再要求单独运行其他 `.bat`，主仓库也不得提交 Voicebox 上游源码、模型、声音档案或运行缓存。首次安装需要下载较多依赖，耗时取决于网络；后续再次运行应自动复用或启动已准备好的服务，独立页面地址为 `http://127.0.0.1:17493`。配置中的音频模型候选应自动出现“本地 Voicebox / Voicebox”；普通音频节点切换后应读取 Voicebox 声音档案、支持刷新和打开独立 Web 页面，未选择档案时明确阻止生成。生成应通过本地 Agent 安全代理或 Vite 开发代理提交 `/generate`，轮询 `/history/{id}`，完成后读取 `/audio/{id}` 并保存到现有 localforage 音频缓存；暂停画布生成时还应请求 Voicebox 取消任务。Script 第二步角色声音应允许每个角色单独绑定声音档案并生成三个 seed 候选，选定结果继续同步为 Seedance `voiceLock` 参考；切换角色档案后旧候选应清空。Voicebox 不接受单次参考音频，连接上游音频时应提示先在 Voicebox 页面把样本加入档案，不得静默丢弃参考。

- Voicebox Windows 首次安装兼容：Windows/Python 3.11 不得从源码编译缺少预构建 wheel 的 `pyopenjtalk`，应改用保持 `import pyopenjtalk` 兼容的 `pyopenjtalk-plus 0.4.1.post8` Windows wheel，并补齐其余日语分词依赖；安装失败后 `setup-complete` 不存在时，重新运行 `start-web.bat` 应复用已有虚拟环境继续安装，无需删除整个 Voicebox 目录。

- Voicebox 模型缓存目录：统一启动脚本应同时设置 `VOICEBOX_MODELS_DIR`、`HF_HOME`、Hugging Face Hub/Xet/Assets、Torch 和 XDG 缓存环境变量，使 Voicebox 与 Transformers 后续下载统一保存到项目内 `voicebox/.runtime/models/`，不得继续写入 `C:\Users\<用户>\.cache\huggingface`；已有全局缓存只按用户明确要求执行一次性迁移，不得由启动脚本自动搬走其他项目共享的模型。

- Voicebox Web 生成状态反馈：点击金色生成按钮后，提交阶段按钮应展开显示“生成中…”和旋转图标；异步任务进入后台后，输入区下方应持续显示当前生成数量及“完成后自动播放并进入右侧记录”的说明，任务完成时显示包含音频时长的成功提示，失败时继续显示原有错误提示。状态只订阅现有任务队列，不新增轮询；后台仍允许继续提交下一条音频。
- Voicebox 画布档案直连：画布选择声音档案后，每次生成都应通过开发代理或本地 Agent 固定白名单从档案列表读取真实档案，并读取 Voicebox Web 生成设置，把档案 ID、档案引擎、`1.7B` 模型规格、长文本分段、交叉混合和标准化设置提交到 Voicebox `/generate`；仍在运行旧版 Agent、暂不支持生成设置路径时应自动使用 Voicebox 默认值，不得把 `unsupported Voicebox API path` 显示为生成失败。画布不得命中本地或共享音频结果缓存而跳过 Voicebox；生成完成后，Voicebox Web 历史应出现同一次任务，画布音频节点顶部应显示档案名称，“信息”中应能核对档案 ID、任务 ID 和实际引擎；重试相同文字也应创建新的 Voicebox 任务并返回该任务的原始音频。

- 视频本地高质量音频分离：已有视频的悬浮操作栏应显示“分离音频”；点击后由 `start-web.bat` 静默启动本地助手，首次使用自动准备私有 Python、FFmpeg、PyTorch CUDA 12.8 音频依赖并下载 BS-Roformer 模型，不要求安装 Docker。私有 FFmpeg 应能被分离子进程识别，RTX 3060 等 NVIDIA 显卡应显示 CUDA 可用并参与推理。处理过程中操作栏显示“分离中”且不能重复提交，完成后在原视频右侧生成并连接“人声”和“背景音乐”两个可播放、可下载、可连接到后续视频作为参考音频的本地音频节点；服务未就绪或分离失败时只提示错误，不生成残缺节点。
- 沧元 Omni 与 Seedance 单模型视频参数：选择 `omni-fast` 或 `omni-fast-no-water` 后，画布和视频工作台应显示固定 720p、约 10 秒、仅支持 16:9/9:16，并允许最多 5 张、单张不超过 5MB 的参考图；提交 5 张图时应通过 multipart 重复发送 `input_reference`，不得再进入 Seedance 4 图校验或附带 `duration`、`resolution`、`audio`。标准 `seedance-2.0/fast/mini` 仍保持图片 4、视频 3、音频 1 和 480p/720p 参数；固定分辨率 `seedance-2.0-480p/720p/1080p/4k` 及其 fast/mini 档位应允许图片 9、视频 3、音频 3，且请求不再发送与模型档位冲突的 `resolution` 或 `audio` 字段。画布生成或重试 Seedance 视频时，不应再出现 `seedanceModelFixedResolution is not defined`，请求应能正常进入参数校验和任务提交阶段。
- 画布角色设定图预设：图片节点选择九宫格预设中的“角色设定图”后，默认提示词应要求严格继承参考图的人物身份与原始画风，生成 16:9 白色至浅灰背景的角色制作资料，包含统一服装的全身三面、脸部角度、表情、五官、头发和其他视角；不得再强制真人写实、深色艺术书或个人简介版式，图内如有标签只能使用简短、清晰的中文。
- 长篇故事分阶段审核工作流：Script 节点默认导演提示词应是跨故事通用的可编辑项目设定，并附带可整段复制给 AI 的定制说明、用户追加要求、可选风格/视角/声音/字幕/视频规格和固定返回格式；工作流正式生成时只读取顶部 `【可编辑项目设定】`，不得把 AI 辅助说明注入分镜。旧 Markdown 表格提示词或上一版通用提示词在下次生成时应自动升级，切换故事无需重写提示词。点击规划按钮后，应先逐句提取可追溯故事事实；“单集浓缩”将完整事实提炼为目标数量的核心事实后规划一集，“完整系列”则保留全部事实并分集。每个 10–15 秒视频片段组织 2–4 个相邻核心事实或完整事实；顶部显示浓缩前后事实数、集数和视频片段总数，随后停在第一步等待人工审核。用户点击“下一步：准备资产”后才识别人物/场景/道具，并按人物 `timeStage` 拆分独立角色资产；资产图只在用户明确点击单个或批量生成后产生，全部资产图准备完成后第二步底部“下一步：合成提示词”才可用；第三步提示词只在用户明确点击单个片段或批量合成后生成，不得跨步骤自动调用模型或产生费用。
- Script 分镜表长文本显示：第一步“确认片段”中，右侧状态/操作信息把表格行撑高时，画面描述、光影氛围、对白旁白等可编辑文本框和“最终提示词”入口应同步填满当前行，不再只占顶部约 78px 并在下方留下大片空白；文字超过整行高度后仍可在单元格内部滚动查看和编辑。第三步“合成提示词”中的画面描述、景别、光影氛围、对白旁白、音效和运镜等只读长文本超过最大显示高度时，应出现单元格内部细滚动条，不再直接裁掉后半段；镜号、时长以及表格横向、纵向滚动保持正常。
- Script 节点 AI 项目设定：提示词面板应显示“AI生成项目设定”；打开后隐藏保脸换装等图片快捷模板，默认要求模型根据当前全部连接剧本判断视觉风格、叙事视角、色调光影、镜头节奏、对白旁白、配乐音效、字幕策略和人物时期。模型结果必须包含完整 `【可编辑项目设定】` 字段并先进入预览，解析时应兼容字段加粗、项目符号、标题井号、数字序号、空格和中英文冒号；只有用户点击“替换当前提示词”后才写回 Script 的 `prompt`，不得覆盖现有分镜表 `content`。未连接剧本文本或清理后仍缺字段时应提示错误并保留原设定。
- 长篇故事事实与连续性：每个镜头应保存原文事实 ID、连续性组、人物时期、开始状态、结束状态和转场类型；同组直接续动作才允许自动接入上一镜尾帧，跨年代、地点、人物年龄或身体状态变化时必须新起场景并移除旧首帧引用。死亡、失去、疾病、离别等敏感事实可使用空摇篮、熄灯、散落物件或人物反应等克制画面，但不得改写成健康、团聚或主体仍然存在。
- 分镜规划 JSON 自动修复：事实提取、分批拆镜或遗漏补镜的模型返回无法解析时，应只针对当前返回自动执行一次 JSON 语法修复，不得重新生成或改写内容；修复成功后继续当前流程，仍失败时应显示具体阶段/批次并保存最终原始返回用于排查。Script 错误节点点击“直接重试”应重新进入完整分镜流程，而不是走普通文本生成。
- Script 节点外部生成入口：Script 提示面板右下角的闪电生成按钮应与大弹窗内“自动生成完整分镜”调用同一专用流程，并在完整分镜写入后停留等待人工审核；Script 新旧错误节点点击重试也应进入该流程。此分流只按当前节点类型生效，文本、图片、视频、音频和配置节点仍调用各自原有生成逻辑。
- Script 长任务进度反馈：从外部闪电按钮或分镜弹窗启动完整分镜后，Script 节点加载态应显示当前事实提取/分批拆镜/遗漏补齐阶段、百分比和进度条，不得只显示无法判断是否卡住的“生成中”；其他类型节点继续使用原加载态。
- Script 制作范围与按集生产：提示面板和大弹窗应提供“单集浓缩（推荐）/完整系列”制作范围，并允许设置每集 60–300 秒及“节省成本 / 标准漫剧 / 细拍漫剧 / 自定义”密度。默认“单集浓缩 + 标准漫剧 + 90 秒”应把完整传记浓缩为约 24 个核心事实，只生成 `E01` 和 6–9 个 10–15 秒视频片段；节省成本、细拍漫剧或自定义模式分别调整目标片段区间。模型首次返回数量超出区间时应自动按目标重新合并一次，仍超出则明确失败，不得悄悄写回过量任务。完整系列才保留全部事实并按 `E01`、`E02` 分集，分集边界不得切断同一连续性组中的 `continue` 动作链。旧规划缺少配置签名或制作范围、模式、时长、片段数发生变化时，节点和弹窗必须显示“需要重新规划”，隐藏旧集数与旧提示词进度，并锁定资产、提示词步骤；重新规划完成后节点直接显示最终集数和视频片段总数。重新规划时旧资产图片应作为隐藏复用库保留，新集识别到同名资产后继承已有图片，不得要求全部重新生图。审核、资产识别、资产批量生成、提示词合成和批量视频工作区只处理当前集；跨集重复资产应复用。片段内部只有直接连续关系才自动承接上一片段尾帧，跨集、换场或切断连续性时不得错误绑定首帧。检查点必须包含制作范围、浓缩状态和原始事实数，配置变化后不得续用不兼容检查点。
- Script 动态提示词批量合成：第三步顶部、底部和画布节点只统计当前制作模式中的动态镜头；批量合成只请求尚未生成 `videoMotionPrompt` 的动态镜头，跳过静态事实镜头和已有结果。任务可暂停，已完成结果应立即保留，再次点击时显示并继续处理剩余数量；静态镜头在表格中明确标记且仍允许按需单独合成，不得因 158 个事实分镜误导为需要生成 158 个视频。单镜返回非法 JSON 时应自动修复并最多重试两次，仍失败则在对应镜头保存错误并继续后续动态镜头；顶部显示失败数，再次执行只重试失败/剩余镜头。
- Script 资产批量恢复：一键生成所有资产时应把运行/中断/暂停/完成状态、总数、成功数和失败数写入 Script 节点元数据，并在每张图片完成后持久更新。关闭再打开 Script 弹窗应继续显示当前进度；页面刷新或热更新无法恢复旧网络请求时，应把遗留 loading 资产恢复为待生成并显示“上次任务已中断”，按钮改为“继续生成剩余 N 个”。继续时只请求没有可用图片的资产，已有结果不得重复生成；部分失败时不得提示全部成功。当前集资产已经全部准备完成时，即使元数据里仍保留之前重新识别失败的历史错误，也不得继续显示红色“识别失败”提示或误导用户认为第三步不可用。
- Script 真人写实资产：角色资产最终提示词不得再强制“非写实虚拟角色、2.5D、动画或漫画、避免真人脸”。写实/真人/纪实项目应锁定真人演员定妆资料、真实中国人物面部骨相、自然皮肤发丝、真实布料和现实光影；动画、漫画、3D、水墨等项目才保持对应风格。第三步合成提示词和 Seedance 参考提示也必须继承项目画风；资产右侧编辑面板应分别显示可编辑的原始提示词和只读的实际提交提示词，两者生成路径必须使用同一提示词函数。
- 音频设置拖动：普通音频节点和配置节点里的“音频设置”浮层应支持拖动非输入/按钮区域上下左右移动；火山“音色库”和“声音复刻”弹窗也应支持拖动顶部标题栏、说明区和卡片空白区，拖动后输入、选择文件、试听、复制 ID、选择音色和滚动列表仍保持正常。
- 火山声音复刻闭环：火山 OpenSpeech 音频设置中应出现“声音复刻 / 上传自己的声音”入口；上传音频后可提交声音复刻、保存返回的 speaker ID、查询训练状态、播放 demo_audio、复制 ID，并可将复刻音色设为当前音色。后续音频生成使用 `custom_...` / `S_...` 等复刻 speaker ID 时应自动按 `seed-icl-2.0` 资源生成。
