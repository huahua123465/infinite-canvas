# 待测试

- 普通视频生成失败后点击“重新生成”时，应复用失败节点保存的原始提示词；即使上游文本、Composer 内容或连接的参考素材发生变化，重试请求中的提示词正文仍应与首次提交一致，同时仍能恢复原有参考素材。分镜视频应继续优先使用已保存的最终提示词。

- Script 合成提示词弹窗与视频最终提示词弹窗：编辑区不再重复显示整段高亮文本；脚本弹窗仍保留本镜头资产引用标签，视频确认页仍应保留最终提示词编辑、资产标签、自动保存和生成请求行为。
- 分镜视频最终提示词初始显示：打开弹窗后，长提示词应直接在可滚动文本框中完整显示，不需要先点击文本框；输入、滚动、@ 资产菜单和自动保存仍应正常。
- Script 第三步导演脚本式视频提示词：合成结果应按视频约束、场景设定、人物设定、站位设定、画面时序、光影与氛围组织；人物资产必须明确执行者/被照护对象职责，同一人物多个时期不得无事实依据同时绑定，动作时间轴必须写清身体部位、作用对象和物理结果。格式或语义校验失败时应只重试当前片段，不终止整批。

- Script 第一/三步编剧质量与默认声音：第一步每个镜头操作栏应可打开并编辑编剧场景卡（目标、阻力、失败代价、人物策略、2-4 个因果动作、阻力反作用、动作转折、结果、价值变化和起止状态）；保存场景卡后应清理该镜头旧的第三步提示词并解除本章旁白锁定。第三步重新合成时，四段时间轴应逐段继承场景卡动作链，明确阻力→转折→结果、资产绑定、环境声/对白/旁白和最后稳定落点；模型输出未覆盖动作链时应被格式检查拦截。没有明确关闭设置时，待审核视频的“生成声音”应默认开启，提示词中应显示“生成声音：开启”。

- Script 完整系列章节节点与共享资产：新建 Script 后选择“完整系列”，应可填写目标章数（例如 8 章）；重新规划后实际章节数应在连续性组不被切断的前提下按目标收口。第一步章节状态栏点击“同步章节节点”，画布应在系列主节点下方生成对应数量的章节 Script 节点；双击或点击“打开本章制作”应打开系列主节点并自动切到正确章节。章节节点只作为引用视图，不得复制事实、提示词和资产库；不同章节识别到同名资产时继续复用主节点资产，删除系列主节点时其章节代理节点应一并删除。

- Script 系列资产显式导出：系列主节点悬浮操作栏应显示“导出资产”，提示该动作不会自动生图。当前集资产未全部准备完成时应明确提示缺失数量并打开第二步；全部完成后点击应立即显示导出进度，只把已经生成或上传的共享资产更新为画布角色、场景、道具节点，不得调用图片模型，也不得自动生成第二集或后续章节资产。切换到下一集后，仍需用户在第二步明确识别并生成新增资产。

- Script 分章旁白锁定与音画提示词：完整系列的每一章在第一步应显示按镜头汇总的旁白主稿、中文字符预算和超时/内部指令检查；旁白超出片段可朗读时间或含“与同时间段可见动作同步”等内部说明时不得锁定。锁定后当前章“对白旁白”列不可编辑，未锁定不得进入资产和提示词步骤；修改任一分镜后应自动解除锁定。第三步模型不得改写或遗漏锁定旁白，保守兜底应把旁白连续分配到前三段时间轴、把引号内人物原话单独写成对白，并且不得再把同步说明作为声音朗读。

- 3D 全景内置插件模块完整性：安装“3D 全景节点”时，`panorama.js`、`three-0.180.0.module.js` 和版本匹配的 `three.core.js` 应依次从当前站点以 JavaScript 返回，不再出现 `Failed to fetch dynamically imported module`。安装后连接一张等距柱状全景图，应可拖拽旋转；切换图片、删除节点、禁用或卸载插件后不得残留动画、全局指针监听、纹理或 WebGL 上下文。

- 前端依赖安全与主题回归：移除项目唯一的 `ProConfigProvider` 包裹和未实际使用的 `@ant-design/pro-components` 后，`npm audit` 应保持 0 vulnerabilities；浅色和深色模式下首页、画布、设置弹窗、模型脚本编辑器及 Ant Design 消息/弹窗应继续使用现有 `ConfigProvider` token 正常显示。关闭更新前启动的 Vite 进程并重新运行 `start-web.bat` 后，版本弹窗的当前版本应同时刷新为 `v0.8.0`。

- v0.8 可见版本标识：重新启动 Vite 开发服务或重新构建静态前端后，画布右上角版本入口和“版本更新”弹窗的当前版本应显示 `v0.8.0`；版本号继续由根目录 `VERSION` 单一注入，不应修改画布组件写死文案。本次只更新可见版本标识，第三阶段仍需人工回归，正式 CHANGELOG 归档和 `v0.8.0` tag 尚未创建。

- 官方 v0.8 第三阶段自定义模型调用脚本：设置的“模型”页底部应按图片、视频、文本、音频列出当前已选模型；同一个模型值在不同媒体类型下应保存独立脚本，刷新页面后仍从 localforage 恢复。编辑器应显示可用变量、返回要求、安全警告和 OpenAI/Gemini 模板；保存空内容或点击“恢复原生调用”后，图片、文本、视频、音频必须继续走现有 OpenAI、Gemini、Ark、沧元、Seedance、火山或本地渠道。设置脚本后，图片需验证文生图、图生图和蒙版参数，文本需验证流式增量输出，视频需验证脚本自行提交/轮询后返回 URL 或 Blob，音频需验证 URL、base64、Blob 与参考音频参数；视频脚本遇到参考视频或参考音频时必须明确阻止，不能静默丢弃素材。脚本异常应显示错误且只影响当前请求，清空脚本后原生调用立即恢复；音频脚本缓存键必须包含脚本内容且不得误用共享试听缓存。脚本能读取当前渠道 API Key、访问任意网络并处理本地输入，只能运行可信代码。完整范围和提交见[官方 v0.8 合并记录](/docs/progress/official-v0.8-merge-notes)。

- 官方 v0.8 节点插件第二阶段：同事拉取代码后，“节点插件”应首先显示“内置可选”页签和便利贴、HTML、Markdown、SVG、3D 全景五项；仅打开管理器不得安装、启用或执行任何内置插件。点击单项“安装”后才应加载仓库内 `/plugins/` ESM、注册对应节点并写入 localforage，禁用/卸载后保持原有节点数据。便利贴应支持编辑、换色、衍生文本和正文拖动；HTML 的 `{{input}}` 应以文本注入，iframe 不得获得主页面同源权限或发起 connect/form 请求；Markdown 中的脚本、事件属性和危险链接不得执行；SVG 中的脚本、`foreignObject` 和外部引用不得保留；3D 全景应使用上游图片旋转查看，节点切换图片、禁用或卸载后不得残留动画、全局指针监听或 WebGL 上下文。无网络环境下内置插件仍应可安装，原有 Script、Workspace、Provider 和生成链路不得回退。完整实现和提交见[官方 v0.8 合并记录](/docs/progress/official-v0.8-merge-notes)。

- 官方 v0.8 节点插件第一阶段：画布右上角应可打开“节点插件”，官方列表应能解析清单中的相对 `entry` 并安装，第三方 URL、本地 `/plugins/index.json` 与 `VITE_DEV_PLUGINS` 插件也应按各自入口发现或加载；安装、启用、禁用、来源更新和卸载后，双击创建菜单、连线创建菜单、底部工具栏、小地图、节点内容、编辑面板、插件工具栏及上游文本/图片/视频/音频资源应随注册状态正确变化。双击画布打开“选择节点”菜单后，点击菜单外区域应立即关闭；便利贴等带编辑按钮的插件节点应支持双击正文进入编辑，并可从正文非交互区域向任意方向拖动画布位置；按钮、输入框、链接、iframe、全景画布等交互区域不得误触发节点拖动。插件渲染或操作异常只能影响当前插件节点，不得让整张画布白屏；禁用或卸载插件后已有节点数据不得删除，应显示“缺少插件”，重新安装并启用同 ID 插件后应恢复渲染。Script、Workspace、Group、分镜三步审核、沧元、Seedance、VoxCPM、本地 Agent 与现有生成链路必须保持原行为；安装第三方插件前应明确提示其代码可访问浏览器本地数据和 AI API Key。完整范围、同事拉取后的安装方式和后续阶段见[官方 v0.8 合并记录](/docs/progress/official-v0.8-merge-notes)。

- v0.7.1 构建与协作更新：同事从 `custom/jt-vite-merge` 拉取后，重新运行 `start-web.bat` 应无需修改源码即可进入项目；全站 Agent 应继续读取当前画布并执行/撤销操作，组节点、Script 资产引用、视频任务轮询、火山音频保存及相关 Ant Design 弹窗/模型下拉应保持正常。`streamdown` 应同时存在于 npm 与 Bun 锁文件，派生仓库推送版本标签时不应再尝试向官方 GHCR 或官方 Pages 发布。

- 视频节点首尾帧查看：已有视频的悬浮操作栏应显示“首帧”和“尾帧”；点击后应从当前视频准确提取对应画面，并在视频右侧生成保持原始比例的独立图片节点。首帧和尾帧分别占用固定位置，重复点击同一按钮时应定位或更新已有节点，不得不断创建副本；刷新项目后图片仍应通过本地持久化正常恢复。

- 脚本节点画布资产工作流：悬浮操作栏点击“批量生成资产”后，应只在 Script 节点右侧按“角色 → 场景 → 道具”横向依次创建彼此独立的资产工作区及独立图片节点，不写入“我的素材”；重复批量导出时应统一恢复该横向排版，工作区内部保持三列网格，批量视频工作区继续接在最右侧，形成从脚本到资产再到视频的单向生产带。随后点击“批量生成视频”时，应根据合成提示词中的 `@资产名` 自动建立资产到待审核视频节点的连线，并写入对应参考图和最终视频提示词。场景多角度锁定图即使保存在脚本资产内部，也应通过对应场景资产节点显示引用连线，避免实际已参考但画布看不出来。

- 本地 VoxCPM 音频生成：`start-web.bat` 应在 `8810` 端口未就绪时静默启动 `D:\work\VoxCPM` 的常驻服务，并在已有服务时直接复用；无 `.git` 元数据的源码包应通过固定开发版本正常安装，Windows NVIDIA 环境检测到 CPU 版 Torch 时应自动安装 PyTorch CUDA 12.8。VoxCPM 的 Hugging Face、ModelScope、Torch、uv、临时参考音频和测试输出应统一保存在项目内 `voxcpm-service/.runtime/`，不得默认写到系统 C 盘临时目录。配置中的音频模型候选应自动出现“本地 VoxCPM / VoxCPM2”。选择后，普通音频节点设置浮层应显示本地服务状态、固定 `WAV 48 kHz`、音色设计和参考克隆两种自动方式；没有上游音频时按声音指令设计音色，连接一个音频节点后应把第一条上游音频作为声音克隆参考，生成和重试都应保留该参考。节点或全局配置中即使残留火山 `speaker`，明确选择 VoxCPM 后也不得被火山自动路由抢占。相同文本、指令和参考音频可命中本地缓存，不同参考音频不得串用缓存；首次生成允许下载并加载 VoxCPM2 权重，服务应允许当前本机 Vite 开发端口访问、只监听本机且一次只执行一个推理任务。
- 本地 Voicebox 音频渠道：根目录 `start-web.bat` 应作为唯一用户启动入口，在同一窗口列出并检查 Canvas Agent、音频分离、VoxCPM、Voicebox 和 Web；Voicebox 未准备时应由该入口自动拉取固定的上游 `v0.5.0`、创建私有 Python 环境、安装官方依赖、构建 Web 并启动 `127.0.0.1:17493`，不再要求单独运行其他 `.bat`，主仓库也不得提交 Voicebox 上游源码、模型、声音档案或运行缓存。首次安装需要下载较多依赖，耗时取决于网络；后续再次运行应自动复用或启动已准备好的服务，独立页面地址为 `http://127.0.0.1:17493`。配置中的音频模型候选应自动出现“本地 Voicebox / Voicebox”；普通音频节点切换后应读取 Voicebox 声音档案、支持刷新和打开独立 Web 页面，未选择档案时明确阻止生成。生成应通过本地 Agent 安全代理或 Vite 开发代理提交 `/generate`，轮询 `/history/{id}`，完成后读取 `/audio/{id}` 并保存到现有 localforage 音频缓存；暂停画布生成时还应请求 Voicebox 取消任务。Script 第二步角色声音应使用当前音频模型，选择 Voicebox 时允许每个角色单独绑定声音档案并生成三个 seed 候选，选定结果继续同步为 Seedance `voiceLock` 参考；切换角色档案后旧候选应清空。Voicebox 不接受单次参考音频，连接上游音频时应提示先在 Voicebox 页面把样本加入档案，不得静默丢弃参考；VoxCPM 渠道继续保留，待 Voicebox 中文效果和稳定性人工确认后再决定是否移除。

- Voicebox Windows 首次安装兼容：Windows/Python 3.11 不得从源码编译缺少预构建 wheel 的 `pyopenjtalk`，应改用保持 `import pyopenjtalk` 兼容的 `pyopenjtalk-plus 0.4.1.post8` Windows wheel，并补齐其余日语分词依赖；安装失败后 `setup-complete` 不存在时，重新运行 `start-web.bat` 应复用已有虚拟环境继续安装，无需删除整个 Voicebox 目录。

- Voicebox 模型缓存目录：统一启动脚本应同时设置 `VOICEBOX_MODELS_DIR`、`HF_HOME`、Hugging Face Hub/Xet/Assets、Torch 和 XDG 缓存环境变量，使 Voicebox 与 Transformers 后续下载统一保存到项目内 `voicebox/.runtime/models/`，不得继续写入 `C:\Users\<用户>\.cache\huggingface`；已有全局缓存只按用户明确要求执行一次性迁移，不得由启动脚本自动搬走其他项目共享的模型。

- Voicebox Web 生成状态反馈：点击金色生成按钮后，提交阶段按钮应展开显示“生成中…”和旋转图标；异步任务进入后台后，输入区下方应持续显示当前生成数量及“完成后自动播放并进入右侧记录”的说明，任务完成时显示包含音频时长的成功提示，失败时继续显示原有错误提示。状态只订阅现有任务队列，不新增轮询；后台仍允许继续提交下一条音频。
- Voicebox 画布档案直连：画布选择声音档案后，每次生成都应通过开发代理或本地 Agent 固定白名单从档案列表读取真实档案，并读取 Voicebox Web 生成设置，把档案 ID、档案引擎、`1.7B` 模型规格、长文本分段、交叉混合和标准化设置提交到 Voicebox `/generate`；仍在运行旧版 Agent、暂不支持生成设置路径时应自动使用 Voicebox 默认值，不得把 `unsupported Voicebox API path` 显示为生成失败。画布不得命中本地或共享音频结果缓存而跳过 Voicebox；生成完成后，Voicebox Web 历史应出现同一次任务，画布音频节点顶部应显示档案名称，“信息”中应能核对档案 ID、任务 ID 和实际引擎；重试相同文字也应创建新的 Voicebox 任务并返回该任务的原始音频。

- 视频本地高质量音频分离：已有视频的悬浮操作栏应显示“分离音频”；点击后由 `start-web.bat` 静默启动本地助手，首次使用自动准备私有 Python、FFmpeg、PyTorch CUDA 12.8 音频依赖并下载 BS-Roformer 模型，不要求安装 Docker。私有 FFmpeg 应能被分离子进程识别，RTX 3060 等 NVIDIA 显卡应显示 CUDA 可用并参与推理。处理过程中操作栏显示“分离中”且不能重复提交，完成后在原视频右侧生成并连接“人声”和“背景音乐”两个可播放、可下载、可连接到后续视频作为参考音频的本地音频节点；服务未就绪或分离失败时只提示错误，不生成残缺节点。

- 视频请求模型与失败分流：分镜最终提示词弹窗选择的单镜头视频模型应优先于上游配置节点和全局默认模型，生成中/失败节点应显示请求模型与任务 ID；“查询原任务”只轮询旧任务，“重新生成”必须清除旧任务信息并创建新任务。服务繁忙时自动等待 30 秒后重试一次，素材不适合、内容策略或上游拒绝不应原样自动重试；前台等待超过 5 分钟后应转为低频后台查询，视频工作台与画布使用同一套轮询规则。
- 沧元 Seedance 单模型接入与请求审计：`seedance-2.0` / `fast` / `mini` 应按即梦文档发送 `resolution`、`audio`，参考图最多 4 张、参考视频最多 3 条、参考音频最多 1 条；参考视频单条 4–15 秒、总时长不超过 15 秒且每边 720–2160px。固定分辨率后缀模型应按单模型文档使用图片 9、视频 3、音频 3 的上限，参考视频单条允许 2–15 秒，并由模型名锁定输出档位，不再发送 `resolution`、`audio`。任务创建后节点应显示“请求模型”而非“实际上游模型”，并可复制任务 ID、提交时间、前端路由、完整请求 URL、请求模型和实际 JSON 字段列表，用于核对沧元后台路由。
- 视频模型选择器参考素材提示：视频模型名称右侧显示“图片·视频·音频”的参考素材上限，例如 `4·3·1` 表示最多 4 张图片、3 条视频、1 条音频；已核对标准 Seedance `4·3·1`、固定分辨率 Seedance `9·3·3`、Omni fast `5·0·0`、Omni V2V `0·1·0`、Grok `7·1·0`、Grok 1.5 `1·0·0`、Sora 2 / Sora 2 Pro `1·0·0`；悬浮提示显示完整含义，尚未完成官方文档核对的模型（包括当前文档页未提供单模型入口的 Veo 型号）显示“待核对”。
- 沧元 Sora 2 单模型请求与视频失败分流：选择 `sora-2` / `sora-2-pro` 后，视频工作台、画布配置节点和分镜最终提示词弹窗应只提供 4/8/12 秒、16:9/9:16、生成声音和最多 1 张帧参考图；提交 `/v1/videos` 时使用 `duration`、`aspect_ratio`、`generate_audio`，有参考图时使用 `reference_mode=frame` 与 `images`，不得继续附带 Seedance 的 `resolution`、`audio`、`image_url` 或多媒体参考字段。旧节点残留 10 秒、非支持比例、超过 1200 字符提示词、超大/多张图片或参考视频/音频时应在本地明确阻止。Omni 等任务已经返回 `failed` 且错误为内容审查时，节点应显示“生成失败”并提示修改真人正脸、版权 IP、敏感题材或参考素材；不再显示无意义的“查询原任务”，网络中断或超时仍保留原任务查询。
- 视频生成前本地检查：画布普通视频、分镜最终提示词和视频工作台在提交任务前应共用同一套本地预检；损坏图片、极低分辨率、模型时长/分辨率/画幅、参考素材数量与 Seedance/Grok 素材组合等硬错误应阻止提交，低清晰度、近似纯色、大面积透明、低对比度或画幅差异较大时应允许用户选择“返回调整 / 仍然生成”。检查只在浏览器本地缩小采样图片，不调用额外 AI 接口，不自动修改提示词、模型或参考素材。

- 视频任务恢复：画布视频生成创建任务后应把 `videoTaskId`、平台、模型和端点写入视频节点；生成中或失败节点应显示任务 ID。生成期间刷新页面后，画布应自动续查原平台任务并把成功视频保存回原节点，不应把刷新误判为平台生成失败或重新提交扣费；自动恢复失败时仍保留“查询原任务”，旧节点没有任务 ID 时可手动填写。完整机制与验收项见[视频生成任务恢复说明](/docs/progress/video-generation-recovery)。
- 沧元视频成功结果接回：创建响应同时包含后台数值记录 ID、平台任务 ID 和上游任务 ID 时，应只保存可用于 `/v1/videos/{task_id}` 的字符串任务 ID；轮询遇到短暂网络错误或 404/429/5xx 时应有限重试，不应因一次查询失败把仍在运行的任务判为失败；任务完成后应优先通过带鉴权的 `/v1/videos/{task_id}/content` 保存成片，失败时再降级到 `video_url`，避免临时媒体域名的跨域、防盗链或链接失效导致平台成功但画布未接回。

- 视频结果本地持久化兜底：Seedance/沧元等平台返回远程视频 URL 后，前端直接下载失败时应自动通过本地 Canvas Agent 代理下载，并继续保存为 IndexedDB 本地视频 Blob；需验证本地 Agent 已连接时，隔天重新打开画布仍能播放已生成视频。
- 视频成功结果有效性校验：平台任务标记成功后，前端应验证带鉴权的内容接口、远程 URL 或本地 Agent 代理取得的视频确实包含浏览器可播放的画面；远程地址返回 404、空文件、错误正文或不可解码内容时不得再以 `bytes: 0` 的成功视频写入画布，应保留任务 ID 和结果地址并提示优先“查询原任务”，避免用户因误判失败而重复提交扣费。

- 图片结果本地持久化兜底：沧元等平台返回 `tmp.cangyuansuanli.cn` 一类远程图片 URL 后，浏览器因 CORS、防盗链或临时地址限制无法直接下载时，应自动通过本地 Canvas Agent 的媒体代理取得图片 Blob，并继续保存到 IndexedDB、在画布显示生成结果；浏览器和 Agent 都失败时应保留结果地址供人工取回，不得只显示无上下文的 `Failed to fetch`。根目录一键启动脚本应从当前 Canvas Agent 源码启动，避免旧 `dist` 缺少媒体代理接口。
- 沧元图片成功结果接回：异步图片响应应兼容标准 `data[].url`、顶层/嵌套 `result_url` 和 `result_urls[]`，并识别大写 `SUCCESS` 等完成状态；响应同时出现后台数值记录 ID、平台任务 ID 和上游任务 ID 时应保存可用于查询的字符串任务 ID。浏览器与本地 Agent 都无法下载远程结果时，只要图片 URL 仍可直接显示，就应先回填画布并保留远程地址，不得把已扣费成功任务显示为无结果。

- 图片生成参考图确认：普通图片节点连入参考图后，提示面板应显示“将传入参考图：图片1、图片2”；当提示词里通过 `@` 点选图片标签后，应额外显示“已 @ 引用：图片1/图片2”，用于确认本次图生图请求会带上这些参考图，且提示词中的图片编号能对应到真实参考图。

- 画布失败节点提示词修改：图片/批量图片等生成失败节点应同时提供“修改提示词”和“直接重试”；点击“修改提示词”只打开当前节点的提示词面板并保留原提示词，用户修改后再手动生成，不应立即重新提交。

- 画布提示词引用编辑：普通图片/视频节点提示词面板失焦时应显示 `图片1` 等参考素材蓝色高亮预览；单击进入编辑后应切回原生 textarea 输入层，显示浏览器真实光标，点击哪里就在哪里插入内容，不应出现光标位置和实际插入位置错行或偏移。

- 画布提示词放大编辑：普通图片/视频/音频/文本生成提示词面板右上角应显示放大编辑按钮；点击后打开居中的大尺寸提示词编辑浮层，仍可继续输入提示词、选择模型、调整图片/视频/音频设置、使用 AI 改提示词和直接生成；点击浮层外部或收起按钮应关闭浮层，已输入提示词和已修改设置应保留并同步到节点。

- 视频主参考图提示：视频工作台参考图列表第一张应显示“主参考图”；画布视频生成配置节点应在视频模式下显示“主参考图 图片1”；普通视频节点提示面板在存在图片引用时应提示第一张连入或 @ 引用的图片会作为视频主视觉参考。

- 沧元算力 Seedance 视频参考图传参：当视频生成同时带参考图和参考视频/音频时，应把第一张参考图作为 `image_url` 主参考图传给 `/v1/videos`，其余参考图再放入 `reference_images`，避免沧元返回 `multimodal video/audio references require at least one reference image`。

- 沧元算力视频分辨率联动：当选择 `seedance-2.0-1080p`、`seedance-2.0-720p`、`seedance-2.0-480p`、`seedance-2.0-4k` 等模型档位时，视频设置面板应自动显示对应分辨率并同步 `vquality`；从设置面板点击同系列可用档位时，应自动切换到对应模型并刷新价格，不再出现“1080p 模型 + 720p 参数”的冲突。无固定档位的 Seedance 模型仍可手动选择分辨率。

- 沧元算力模型价格显示：模型选择器应自动读取 `https://ai.cangyuansuanli.cn/api/pricing`，在沧元算力渠道的模型名后显示价格；按次/按条计费显示单价，按秒计费的视频模型在视频工作台、画布视频节点和最终提示词弹窗中应按当前视频秒数显示估算金额；重新拉取单个渠道或全部模型后应同步刷新价格表，使新增分辨率档位无需刷新页面即可参与估价；价格接口读取失败时不应影响正常选择和生成。

- 沧元算力模型渠道接入：配置里应支持新增“沧元算力”调用格式，默认 Base URL 为 `https://ai.cangyuansuanli.cn`；填写 API Key 后可通过“拉取模型”读取 `/v1/models`，并能把 `omni` 归类到视频模型、`gemini-banana-*` 归类到图像模型。文生图应走 `/v1/images/generations`，图生图应同步走 multipart `/v1/images/edits` 并直接读取 `data[].url`；视频生成应走 `/v1/videos` 和 `/v1/videos/{task_id}`，完成后优先取 `video_url`，并避免误走方舟 Ark 的 `/contents/generations/tasks`。

- 沧元算力图片模型新接口：画布生成配置节点展开模型下拉后，应能直接选择 `gpt-image-2-*`、`nano-banana-*` 等沧元图片模型，点击浮层不得触发画布平移或取消选择；图片请求应使用 `aspect_ratio` 与模型匹配的 `image_size` / `output_resolution`，固定 1K/2K/4K 模型不得再发送像素 `size` 或冲突 `quality`；提示词明确写出“宽高比改成/设为 W:H”时，该比例应覆盖节点中的旧比例，避免结构化参数与编辑要求冲突。存在参考图时应统一通过同步 multipart `POST /v1/images/edits` 重复提交同名 `image` 文件字段，最多允许 9 张参考图，不得附带 `async=true`，服务端意外返回任务 ID 时仍按 edits 路径轮询兜底；纯文生图仍走 `/v1/images/generations`。通过 `@` 菜单选择图片后，输入框、配置节点转换和最终请求应全程保留 `@图片N`；旧提示词中的裸 `图片N` 引用应在请求前自动补全 `@`，multipart 顺序应写进编号说明，单图编辑还应明确要求基于原图且保留未指定修改的主体、人物数量、姿态、服装、场景、构图与画风。本地 `blob:` / IndexedDB 参考图必须转成标准 JPEG、PNG 或 WebP 文件后再发送；无效 Base64、空图片和单张超过 10MB 应在前端直接显示中文错误。

- 沧元算力视频进度显示：视频生成轮询 `/v1/videos/{task_id}` 时应读取平台返回的 `progress`，节点进度文案显示真实百分比；任务完成仍优先取 `video_url`，失败时应尽量展示 `error.message` 和 `error_code`，便于判断是排队、生成中、素材不合规还是内容策略拦截。

- 沧元算力视频结果 URL 兼容：`/v1/videos/{task_id}` 完成后应能从 `video_url`、`video.url`、`raw_data.video_url`、`data.video_url` 或 `data.url` 取到成片，重点验证 `seedance-2.0-*`、`omni-*` 和 `sora2` / `openai-sora2`。

- 沧元算力 Grok 视频专用端点：`grok-video` / `grok-video-1.5` 应走 `POST /v1/video/generations` 和 `GET /v1/video/generations/{task_id}`，支持 `seconds` / `duration`、`aspect_ratio`、`resolution`、`image_urls`、`video_url`；其中 `grok-video-1.5` 必须且只能连接 1 张参考图，纯文生或视频参考应直接提示。

- 分镜角色资产统一设定图：脚本节点第二步“准备资产”识别角色时，同一人物的不同年龄/时期状态应拆成独立角色资产，例如“白秋妹·年轻时期”“白秋妹·成年时期”，不应把多个年龄阶段塞进同一张角色图；角色资产图生成应统一为横向 16:9 单角色设定图，包含正面全身主视图和同一年龄状态的侧面/背面/半身/表情参考，背景简洁且无文字、Logo、水印、多人合照或成长时间线；第三步合成提示词应按镜头内容引用对应年龄状态的资产。
- 3D 导演台新版运镜升级：主导航或画布入口进入 `/director-desk` 后应显示导演台首页和独立工程列表；进入工程后可使用 WASD 掌镜，按 `R` 或 `Enter` 连续记录、更新摄影机轨迹点，并通过统一时间轴播放人物、道具与摄影机运动。人物路线应支持添加、插入、拖动和动作预设，摄影机应支持目标跟踪、运镜预设、导演路线/成片监看、路径碰撞及 WebM 参考视频导出。原有模型导入、全景连接、主题会话和截图能力应继续可用；从具体画布进入时，关闭按钮应返回当前画布，“发送到画布”应把截图追加为当前画布的图片节点。
- 分镜视频多版本收纳：同一待审核视频节点多次生成后，画布外层只应显示当前最新视频，最新视频应轻微覆盖在对应镜头卡片上方，不再向右侧连续铺开遮挡其他镜头；镜头卡片底部应显示“所有视频”入口，点击后可在弹窗中查看该镜头全部历史视频版本，并标记当前最新版本。
- 分镜场景多角度批量生成：脚本节点第二步“准备资产”的“场景”标题旁应显示“一键生成全部多角度锁定图”入口；点击后只对还没有锁定图的场景生效，并按 3 张一组并发生成；生成中的单个场景卡片应显示“暂停生成”并可单独停止；只有点击批量生成后，标题旁入口才切换为“一键暂停全部”，单个场景生成时标题旁入口仍保持一键生成状态；顶部“暂停生成”也能停止全部，已完成的锁定图应保留并继续作为后续视频的“场景锁定”参考。
- 分镜视频场景一致性：脚本节点第二步的场景资产卡片应显示“生成多角度锁定图”入口；点击后生成一张主视角更大、辅视角更小的同场景多角度 sheet，而不是在画布右侧铺开多张角度节点。后续创建待审核视频节点时，如果该场景已有多角度锁定图，应自动作为“场景锁定”参考图补入参考数组；最终生成提示词应说明该 sheet 只用于理解空间关系，优先读取放大的主视角，不要生成分屏、拼图或多宫格画面，并继续约束场景空间结构、门窗位置、材质、道具摆放、光线方向和单一主运镜。
- 分镜场景锁定图预览：脚本节点第二步的场景资产卡片中，已生成的多角度锁定图应支持点击放大查看；大预览弹窗应完整显示图片，不裁切，并保留“重做多角度锁定图”入口，便于检查同一场景不同机位的一致性。

- 分镜场景锁定图横向比例：重做或批量生成多角度锁定图后，图片整体应是横向 16:9 宽画布，主视角更大、辅视角更小并铺满卡片，效果应接近“湖南湘西县城广场”多角度图，不应生成竖版长图、窄图、黑边或大面积留白。
- 分镜角色声音一致性：脚本节点第二步只在角色资产卡片保留本地 VoxCPM“角色声音”试听和一键生成/重做入口，右侧资产详情不再重复显示音频模型、speaker ID、音色库、试听台词或声音提示词。点击后必须固定使用项目内 `VoxCPM2`，不受全局 OpenAI/火山音频模型影响；系统应根据角色本名、时期、描述、视觉提示词和作品风格自动生成声音指令，并优先从分镜“对白旁白”提取该角色台词，没有台词时再按人物类型生成 15 秒以内的试听文案。
- 分镜角色声音自动理解：本地 VoxCPM 角色声音应把“妹妹/姐姐/女孩”和“哥哥/弟弟/男孩”正确识别为对应性别，解析“五岁/8岁”等明确年龄，并区分婴儿、儿童、少年、青年、成年、中年、父母和老人；最终只向 VoxCPM 提交简短明确的年龄、性别、音色、性格、地域口音和表演指令，不得再次拼入整段视觉提示词。分镜试听台词只有明确标注该角色说话时才可采用，旁白不得误归给角色；每次点击重新生成必须使用新随机 seed 并避开旧缓存。无参考音频的角色音色设计应在本地生成 3 个可独立试听的候选，默认使用第一条，用户点击“使用”后应同步更新后续待审核视频节点的角色声音参考；刷新项目后候选音频仍应可播放。声音克隆仍只生成 1 次。若要完全固定多镜头音频，建议关闭视频原生声音并统一后期混音。
- 火山语音合成接入：音频生成应支持火山 OpenSpeech TTS HTTP 接口；当音频模型为 `seed-tts-*` / `seed-icl-*` 或 Base URL 指向 `openspeech.bytedance.com` 时，应使用 `X-Api-Key` 和 `X-Api-Resource-Id` 调用 `/api/v3/tts/unidirectional`，并允许“默认音频声音”填写火山 speaker ID，例如 `zh_female_..._bigtts`。
- 火山角色音色校验：火山语音合成应把 `req_params.speaker` 作为实际音色来源，不再把空值回退为 OpenAI 默认 `alloy`；如果角色和全局配置都没有有效火山 speaker，应直接提示填写 speaker ID，避免女角色生成成默认男声或所有角色共用同一个错误音色。
- 火山角色音色选择：角色声音编辑区应支持手填 speaker ID、从内置火山音色候选中搜索选择，并可按角色文本自动填入推荐 speaker；未手动选择时生成试听应自动使用推荐音色并写回角色，便于试听后继续调整。
- 火山语音错误排查：火山 TTS 失败时应尽量展示接口返回的原始错误码、错误信息和 logid；如果用户误把控制台实例名 `TTS-SeedTTS2...` 填到音频模型里，应自动归一为接口要求的 `seed-tts-2.0`。
- 角色音色渠道隔离：角色上保存的火山 speaker ID 只应在火山 OpenSpeech 音频模型下生效；使用 OpenAI TTS 时应继续映射为 OpenAI 支持的 `alloy`、`coral`、`nova`、`onyx` 等 voice，避免把火山 speaker 传给 OpenAI 导致 `field_invalid`。
- 火山音频自动路由：当本次音色是火山 speaker 但当前默认音频模型仍解析到 OpenAI 等非火山渠道时，应在已配置模型中自动查找 `openspeech.bytedance.com` / `seed-tts-*` 音频渠道发起请求，降低只新增渠道但未切换默认音频模型导致的误路由。
- 火山 speaker 兜底：已进入火山 TTS 请求后，如果上层没有正确传入角色 speaker，应根据音频指令和试听台词自动推荐一个火山 speaker，避免误用 OpenAI 默认 voice 后直接中断生成。
- 角色声音模型选择：脚本节点右侧角色声音编辑区应显示当前默认音频模型，并支持直接切换音频模型；切换后生成角色试听应使用新的默认音频模型，减少用户不清楚当前走 OpenAI 还是火山 TTS 的问题。
- 火山网络错误提示：火山 TTS 请求没有 HTTP 响应时，应显示 Network Error/CORS 方向的提示，避免把浏览器直连 OpenSpeech 被拦截误判成 speaker 或额度问题。
- 火山语音本地转发：火山 OpenSpeech TTS 应优先通过本地 Infinite Canvas Agent 代理请求；本地 Vite 开发环境应提供 `/api/v3/tts` 同源代理，避免浏览器直连 `openspeech.bytedance.com` 时被 CORS 或本机网络策略拦截。
- 火山语音旧版鉴权：音频渠道 API Key 字段应支持填写 `APP ID|Access Token` 或包含 `appId` / `accessToken` 的 JSON，用于旧版控制台 OpenSpeech 鉴权；本地 Agent 代理也应按同样规则转发对应请求头。
- 火山语音音频解析：火山 OpenSpeech V3 HTTP Chunked 返回成功后，应兼容二进制协议帧和逐行 JSON/base64 音频片段，把真实音频 payload 拼接后再保存，避免浏览器音频控件显示 `0:00 / 0:00` 且无法读取 duration。
- 角色声音模型选择稳定性：脚本节点右侧角色声音区的音频模型选择应改用 Ant Design Select，避免 Radix Select 在当前 React 运行时中反复更新 ref 导致 `Maximum update depth exceeded`。
- Seedance 第三步合成提示词：合成 `storyboardPrompt` / `videoMotionPrompt` 时应通过本地 Canvas Agent 运行时读取 `seedance-2.0-5.3.0/seedance-2.0-5.3.0` 技能包，并吸收 `seedance-20` 的导演公式、模式判断、动作/运镜约束、角色一致性、声音提示、资产角色映射、去空话和短片节奏；Agent 未连接时回退到内置规则。提交给模型时只截取这些模块中与第三步直接相关的章节，不得把安全过滤示例、故障排查示例、技能元数据或整包原文重复塞进每个片段。合成结果应更明确区分首帧静态画面和视频运动导演指令，并根据第二步资产清单收口 `assetMentions`，减少虚构资产、过度引用资产、运镜冲突和空泛堆词。使用根目录一键启动脚本测试前，应先重新构建 `canvas-agent`，确保 `dist` 中包含最新技能包读取列表。
- Script 通用编剧融合：传记、叙事、概念短片和完整系列在事实提取（单集模式先完成核心事实浓缩）后，应由本地 Canvas Agent 运行时读取 `infinite-canvas-screenwriting` 技能生成可追溯的“剧作总纲”，Agent 不可用时回退到同契约的内置规则；第一步应展示一句话故事、核心冲突、开场钩子、主角目标、规则来源和风险提示，每个生产片段应携带戏剧功能、当前目标、阻碍、失败代价、人物策略、2-4 个因果动作节拍、阻力反作用、动作转折、可见结果、情节/情感双轨节奏与价值变化，悬停戏剧功能可查看完整场景卡。缺少核心场景字段或仍使用不可拍摄的心理概述时，应在写入前自动按相同事实 ID、片段数和视频预算有限重写；第二步资产优先级和第三步合成提示词应继承当前片段相关的总纲与场景卡，并按同一动作链生成四段时间轴，但所有结构判断只能引用当前事实 ID，不得虚构剧情或绕过“确认片段 → 准备资产 → 合成提示词”。旧规划断点若不含当前场景合同签名，不得复用旧镜头；更换故事后重新规划也应自动走同一流程。
- Seedance 秒级时间轴提示词：第三步每个动态 `videoMotionPrompt` 应固定显示“生成规格 / 参考资产绑定 / 叙事目标 / 起始画面 / N秒时间轴 / 镜头运动 / 光线与画面质感 / 声音时间轴 / 连续性与稳定约束”；N 必须读取当前片段时长，画面时间轴必须由四段连续时间组成，从 0 秒无空档、无重叠地覆盖到 N 秒，最后保留稳定落点。技能包生成、内置规则和安全兜底结果均应采用相同格式；模型返回缺栏目或时间不闭合时不得直接保存为成功结果。
- Script 提示词重新合成：第三步当前集全部动态提示词完成后，顶部按钮不应停留在禁用的“剩余 0 个”，而应显示可用的“重新合成全部 N 个”；点击后先说明无需重做分镜和资产、会再次调用文本模型并覆盖已有提示词，确认后逐条更新且允许暂停。单条提示词仍可通过行尾菜单或提示词详情弹窗重新合成。
- Seedance 提示词来源与可执行兜底：第三步提示词详情和待审核视频确认页应明确显示“技能包生成 / 内置规则 / 安全兜底”，技能包生成项可通过悬停查看实际读取路径；连续安全拒绝后的兜底提示词仍应绑定当前镜头相关角色、场景和道具，只保留一个直接可见事件、一个地点、一个连续动作和一个主运镜，不得再出现“不绑定人物”却实际提交角色图、连续横移跨越多个地点、自然蒙太奇或“家庭生活阶段/生活状态发生变化”等失真措辞。安全改写应保留年少时期、亲人关系、迎来新成员、亲人离世、行动受限和接受照护等必要事实，只调整直白风险表达。角色声音参考只在当前分镜对白明确出现该角色姓名时提交，纯环境声或旁白镜头不得无意义占用音频参考。
- Seedance 参考素材映射：向视频模型提交参考图、参考视频和参考音频时，文本顶部应逐项写明 `图片N/视频N/音频N = @资产名`，并与实际媒体数组顺序完全一致；模型必须能区分角色身份、场景锁定、关键道具、首尾帧和角色声音各自控制的对象，不能只罗列“图片1、图片2”却让提示词继续使用无法对应的 `@资产名`。
- 待审核视频生成按钮：最终提示词非空时，“生成视频”不得因为同名角色、人物时期或场景候选的模糊匹配而置灰；未绑定参考只显示可操作提醒，点击后继续进入统一视频生成预检并允许用户确认“仍然生成”，只有模型参数缺失、素材无法读取等确定性错误才硬阻断。同一角色已有当前时期参考图时，不应再因为“我的素材”或其他时期候选中出现相同本名而误报缺少角色资产。
- Script 固定视频预算与音画对齐：单集重新规划后应严格使用当前制作模式计算出的目标视频数，不因跨地点或事实较多而继续增加；每镜计划应区分一个 `visualBeatIds` 主要可见事实和若干 `voiceoverBeatIds` 背景事实，第一步列表显示“主要画面 / 旁白事实”数量，资产与画面只按主要事实选择一个场景和准确人物时期。第三步合成应要求四段画面只推进同一动作，VO 时间段与画面分段完全一致、中文旁白不超过每秒约 4 字、最后 1-2 秒只保留稳定落点；多场景、旁白超时、音画时间不一致或结尾新增剧情时应自动重试而非保存成功。旧规划应显示为配置已变化并要求重新规划，但已生成/上传的资产图可继续复用。
- 分镜视频节点：生成失败时应在节点主体区域清晰展示失败原因；放大节点后提示词、错误信息、参考资产和底部操作区的空间分配应更均衡。
- 脚本节点资产侧栏：视频或提示词相关动作结束/失败后，已选资产的“重新生成图片”按钮不应被无关状态置灰；仅资产生成中或批量资产动作中才应锁定。
- Seedance 最终提示词：当模型把 `@资产名` 和后续描述粘连在一起时，应优先按已有资产名前缀绑定参考图；后续合成提示词应要求资产名后用空格或标点隔开。
- 分镜视频多版本：待审核视频节点点击“生成视频”后应保留为可继续编辑的提示词节点，并在右侧新增独立视频结果节点；多次修改提示词生成时，旧视频和新视频应同时保留在画布中，下一镜首帧默认跟随上一镜最新成功版本。
- 分镜视频连续性：下一镜接入上一镜尾帧时，待审核节点和最终提示词弹窗都应明确显示首帧来源，例如“首帧来自第 1 镜 v1 尾帧”；未接入时应显示“未接入上一镜尾帧”。
- 分镜视频最终提示词弹窗：视频生成设置和最终提示词应自动保存到当前镜头，修改后显示“已自动保存”，关闭后再次打开仍保持上次设置。
- 分镜视频最终提示词固定操作区：打开最终生成提示词弹窗后，弹窗高度应保持在浏览器可视区域内，外层页面不应随内容滚动；滚动视频设置、参考资产和提示词等中间内容时，顶部镜头标题与关闭按钮、底部说明与“生成视频”按钮应始终可见并可直接操作。
- 分镜视频最终提示词视频设置：最终提示词弹窗内打开视频设置后，点击分辨率、比例或时长选项不应触发外部点击关闭，弹窗应保持打开并正常自动保存设置。
- 分镜视频最终提示词资产选择：最终生成提示词弹窗应直接显示当前剧本资产、场景锁定图和我的素材候选；资产卡片负责加入或移除实际提交的参考图，首次加入时自动在光标位置插入 `@资产名`、显示缩略图并立即保存，输入或删除文本中的 `@资产名` 不得静默改变实际参考图数组；修改提示词中间内容时，光标不应因为自动保存跳到文本末尾。
- 分镜视频必要资产绑定：第三步合成提示词后应根据当前片段的事实人物、人物时期和地点自动补齐对应角色资产与一个核心场景资产，再按提示词保留真正使用的关键道具；创建待审核视频节点时，只要任一必要资产尚未生成或上传就应明确列出缺失资产并停止创建，不能只绑定道具后继续生成。最终提示词弹窗中的参考图选择应独立于文本 `@资产名` 保存，删除文字不得静默移除已选图片；资产卡片必须显示“已加入/未加入”和本次实际提交数量，提示词出现但未加入的角色或场景应阻止生成。实际请求提示词还应说明普通主体参考图负责锁定角色身份、服装、画风和关键道具外观，避免参考图虽已上传却没有明确控制职责。
- 分镜视频子弹窗外部点击关闭：最终生成提示词、参考资产编辑和所有视频弹窗应支持点击弹窗外部区域关闭；在弹窗内部输入、滚动、点击按钮、选择素材、打开模型/设置下拉或使用 `@` 资产菜单时不应误关闭。
- 分镜视频连续性编辑：编辑参考时应能从上一镜多个视频版本的尾帧中手动选择一个设为首帧，也能移除当前尾帧首帧；点击“保存参考资产”后，带空格的完整尾帧引用（例如 `@第 2 镜 v2 尾帧`）应保持图片绑定并同步到最终提示词，生成视频时实际传入该首帧，不得截断成未绑定的 `@第`。
- 分镜视频尾帧回填：打开已有项目时，旧的分镜视频结果如果还没有尾帧 metadata，应自动从视频中提取尾帧并出现在下一镜“连续性首帧”候选中。
- 分镜视频旧结果兼容：旧项目中已生成的视频即使缺少新版分镜结果字段，只要仍连接在上一镜待审核视频节点后，也应被识别为上一镜结果并参与尾帧回填和下一镜首帧候选。
- 分镜视频尾帧识别兜底：旧视频结果即使没有新版字段或连线，只要位于同一个视频工作区且位置靠近上一镜待审核视频节点，也应尝试归属上一镜、自动截取尾帧，并出现在下一镜“连续性首帧”候选中。
- 脚本节点画幅设置：脚本节点整体提示词中的“视频生成设置/比例”支持 `16:9`、`9:16`、`3:4`、`4:3`，后续资产图、分镜图、待审核视频节点和视频生成请求都应使用该比例；普通视频接口不应再把 `3:4` 近似成 `9:16` 或把 `4:3` 近似成 `16:9`。
